# Типизированные узлы и маршруты

## Ответственность

`domain::NodeRole` определяет роль независимо от названия и категории редактора.
Источники не имеют входов, обработчики принимают и выдают данные, потребители
не имеют выходов. Каталог редактора группирует узлы по этим же правилам.
Граница узла использует семантические роли общей палитры: Link для источника,
Mid для обработчика и Highlight для потребителя.

Все графики — потребители. `FFTView` получает стереоспектр; выбор канала и
способ его отображения выполняется desktop-представлением. Для изменения
данных маршрута используется отдельный `SpectrumMerge`, а не график.

## Контракты

| Тип | Форма | Назначение |
| --- | --- | --- |
| audio, window, windowed | Два вектора | PCM, накопленное окно и окно после оконной функции |
| stereo-spectrum | Два вектора | Спектры левого и правого каналов |
| spectrum, mel | Вектор | Спектр и Mel-полосы, разные семантические типы |
| history | Матрица | История `[кадр][полоса]` в кольцевом буфере |
| scalar | Одно число float | Численный результат анализа или диагностика |
| wled-packet | 44 байта | WLED AudioSync v2, фиксированный little-endian формат |

Форма массива не разрешает соединение: Mel и spectrum несовместимы, как и
scalar с history или пакет с численным массивом. Domain проверяет индекс
порта и его смысл; редактор использует тот же контракт. При изменении типа
узла прежние соединения удаляются, при сокращении числа выходов удаляются
связи исчезнувших портов. Несколько связей от одного выхода допустимы.

`FrameView` заимствует память только на время обработки. Для очереди используется
`BufferPool`/`RetainedFrame`, включая владение байтами пакета. PreparedGraph
готовит память заранее; новые операции маршрутизации и кодирования не выделяют
память в обработке кадра. GUI-снимки и отображение хранят данные отдельно.

## Новые элементы

- **Splitter / Разделитель:** 2–8 выходов одного выбранного типа. Передаёт кадр
  на все ветки без копирования полной истории.
- **Switch / Переключатель:** 2–8 выходов; параметр `selected` выбирает активный
  выход, индексы начинаются с нуля. Остальные получают типизированные нули.
- **Gate / Разъединитель:** один вход и выход выбранного типа; `enabled`
  пропускает данные или выдаёт нули.
- **ScalarReduce / Численный анализ:** максимум абсолютной амплитуды, среднее
  знаковое значение или RMS. Для стерео учитывает оба канала; для history —
  последний кадр, чтобы не сканировать всю историю каждый раз.
- **ScalarView / График значения:** потребитель scalar; отображает последние
  128 значений, история принадлежит представлению.
- **WLEDEncode / Пакет WLED:** Mel → wled-packet; усиление и форматирование
  являются параметрами этого обработчика.
- **WLEDOutput / Отправка WLED:** потребляет готовый пакет и отправляет его через
  desktop UDP-адаптер. Без новых кадров адаптер через 300 мс отправляет тишину.

Накопитель `Spectrogram` имеет два выхода: порт 0 — history, порт 1 — scalar
с текущим числом накопленных кадров. Это число ограничено ёмкостью истории.
Временные метки, sequence и discontinuity остаются метаданными каждого кадра.

Пример: `Mel → Splitter → Switch → Spectrogram → SpectrogramView`.
От второго выхода накопителя можно отдельно построить `ScalarView`.
Параллельная ветка `Mel → WLEDEncode → WLEDOutput` независимо отправляет световые
данные. Новая стандартная схема использует именно раздельные WLED-узлы.

Смена selected, enabled, усиления или операции анализа подготавливает новый
план и переносит совместимое состояние. Истории не сбрасываются целиком;
неактивная ветка продолжает получать нулевые кадры. Недоступный источник
распространяет unavailable, а не маскируется под доступную тишину.

## Управление и совместимость

`processing_version=1` проверяется против `DeviceCapabilities`; старые документы
без этого поля означают версию 1. Устройство объявляет поддерживаемые NodeKind
и типы транспорта. Неподдерживаемый узел, тип или версия отклоняются до запуска.
Прошивка должна предоставить capabilities своего набора реализованных адаптеров,
не копировать desktop-возможности автоматически.

Исторические идентификаторы типов 0–6 и их BDSP payload v2 не изменены. Scalar
и пакет используют payload v3 и подписку v3. BDSP framing и TCP/UART-кодек общие.
Старый peer явно отказывает в новой версии; новые типы не выдаются за старые.

Файлы настроек остаются JSON. Отправка ApplyGraph удалённому ядру проецирует
документ на `version`, `processing_version`, `graph_id`, параметры узлов и связи.
Позиции, dock-компоновка и настройки интерфейса остаются у клиента; клиент
восстанавливает их после ответа ядра. Неизвестные параметры узлов сохраняются
для совместимости. Эта проекция не применяется к сохранению пользовательского файла.

Полный processing-документ отправляется компактным JSON. После применения
исполнитель переносит совместимое состояние, но бинарный patch-протокол ещё
не вводится. Замена JSON сама по себе не даёт адресного reload: сначала нужны
контракт версии/revision, атомарность применения и измеренная потребность.
Для будущего согласуемого бинарного адаптера доступны
[CBOR, RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html) и
[Protocol Buffers](https://protobuf.dev/overview/). CBOR допускает гибкие структуры,
Protobuf задаёт схему и генерацию кода. Выбор требует оценки конкретных сообщений
и памяти embedded-профиля; новый обязательный dependency сейчас не добавляется.

Старый объединённый `WLED` остаётся совместимым при чтении старых схем, но скрыт
в каталоге новых элементов. Desktop WLEDOutput пока использует один общий
настроенный UDP endpoint; несколько WLED-получателей domain явно отклоняет.
Пользовательские схемы и UUID автоматически не переписываются.

## Проверки

`node_routing_tests` проверяет маршруты и типы, сохранение двух историй при
переключении, скаляры и диагностический порт, отсутствие выделений, владение
пакетом, codec v3 и отказ несовместимых версий/capabilities.
`editor_tests --contracts-only` проверяет реальные QtNodes-связи при изменении
типа и числа портов. `stream_transport_tests --typed-routing-only` проверяет
TCP scalar/packet и UDP отправку готового WLED-пакета с переходом в тишину.
`embedded_sdk_tests` проверяет фрагментированную передачу новых типов через общий
byte-stream adapter. Старые codec goldens и runtime continuity остаются проверками
совместимости. Эти проверки не означают аппаратную приёмку ESP32 или WLED.
