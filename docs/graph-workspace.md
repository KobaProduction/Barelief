# Окна графиков

- Одиночный клик по блоку переключает последнюю внутреннюю область окна с потоком данных. Без внутренней области клик не создаёт её. Фокус во внешнем окне не меняет эту область.
- Контекстное меню создаёт область внутри окна, вкладку или отдельное внешнее окно. Повторное открытие уже показанного графика может создать независимое представление. Меню перечисляет открытые внутренние и внешние представления и позволяет сфокусировать выбранное.
- Команды «Размещение» в заголовке перемещают существующее представление; камера и настройки сохраняются. Внешний график не забирается в основное окно одиночным кликом: создаётся внутреннее представление того же узла.
- Положение потока данных задаётся в настройках графики: снизу, сверху, слева или справа. ADS сохраняет разделители, вкладки, боковые панели и геометрию внешних окон.
- Дополнительные представления сохраняют собственные `instance`, настройки и идентификатор dock в `ui.graph_views`. Все получают кадры одного узла; скрытые представления не перерисовываются.

Регрессии: `qt_workspace_resize_windows` (области, внешние окна, контекстное меню, данные, позиции, восстановление) и `qt_workspace_resize_docking` (разделители, перенос, вкладки, хоткеи). Тесты работают с синтетическим источником и отдельной конфигурацией.

## Общие элементы управления

Навигационные кнопки создаются через `ui::tool_button`, меню подключается через `ui::button_menu`; для обычной кнопки используется `ui::compact_control`. Высота — 24 логических пикселя, цвета и стрелки задаёт только `ui::Theme`. Частные стили кнопок и отдельные размеры для темы, пресетов и обработчика не добавлять.

Пресеты, поток данных, тема и обработчик находятся в верхней панели. FPS показывается только справа в заголовке активного графика, перед размещением; общего FPS в основном окне нет. Пустая нижняя панель скрыта, сообщения и ошибки показываются при необходимости. Упорядочивание, центровка и масштаб встроены в заголовок потока данных. Размер кнопок заголовка — 24 логических пикселя. Внешняя рамка Windows получает цвета общей палитры через DWM; поддержка атрибутов зависит от версии Windows. Проверка: `qt_workspace_resize_chrome`.

## Docking-компонент

Используется [Qt Advanced Docking System 5.1.1](https://github.com/githubuser0xFFFF/Qt-Advanced-Docking-System/releases/tag/v5.1.1), зафиксированный commit `023ce95934fecfd4cf5c672c9c404fabe0f54923`. Библиотека собирается как DLL; её лицензия LGPL поставляется в `bin/licenses`. Перетаскивание вкладок, зоны сброса, нефиксирующий preview, отмена по Escape, разделители и auto-hide предоставляются библиотекой. Перемещение не пересоздаёт renderer. Наша фабрика расширяет только заголовок для общих элементов управления.

`WorkspaceWindow` и `WorkspaceDock` находятся в `presentation/qt/workspace`; DSP, domain и application не знают об ADS. Обращения к стороннему backend ограничиваются Qt presentation. Для замены docking-компонента сохраняются сценарии и стабильные идентификаторы, заменяется этот адаптер. Это граница presentation, а не новый универсальный docking-движок.

Для инвентаризации используется `workspaceDocks()` / `workspaceDock(id)`: неактивная вкладка ADS может временно не иметь QObject-родителя. Поиск через `MainWindow::findChildren` не является полным списком представлений. Область host определяется через dock container, а не через родителя неактивной вкладки.

Новая раскладка сохраняется в `ui.workspace.ads_state`, `backend=qt-ads`, `layout_version=5`. Прежнее поле `state` и неизвестные поля сохраняются. Импорт старой раскладки Qt восстанавливает группы, стороны, видимость и внешнюю геометрию; точные пропорции старого дерева разделителей могут измениться. Новые состояния ADS сохраняют собственное дерево разделителей.

## Навигация

Сочетания отображаются в меню «Отображение»; привычные Ctrl+S/O/C/V остаются без изменений.

| Действие | Сочетание |
| --- | --- |
| Следующая / предыдущая вкладка группы | Alt+Right / Alt+Left |
| Отделить активную вкладку | Shift+F4 |
| Скрыть активную панель | Shift+Escape |
| Фокус на потоке данных | F12 |
| Скрыть / восстановить поток данных | Ctrl+Shift+F12 |
| Выбрать открытое представление | Ctrl+Tab |
| Отменить / повторить изменение схемы (меню «Файл») | Alt+Z / Alt+Shift+Z |

Закрепление в ADS означает сворачивание в боковую auto-hide панель; это не запрет закрытия редакторской вкладки. Переключатель Ctrl+Tab сейчас показывает список представлений, а не полный MRU-интерфейс JetBrains.

Список вкладок находится перед вкладками группы и скрыт, если открыта только одна. Навигация потока данных ограничена содержимым с запасом 160 экранных пикселей; область расширяется при добавлении и перемещении блоков. При pan transform не пересоздаётся, дробное смещение сохраняется, инерционные `ScrollMomentum` события игнорируются. Настройка направления прокрутки ОС не инвертируется повторно приложением.

Подход адаптирован по [документации JetBrains](https://www.jetbrains.com/help/idea/reference-keymap-win-default.html) и разделению preview/drop/cancel в [IntelliJ DockManagerImpl](https://github.com/JetBrains/intellij-community/blob/611d269ff19e2106e1f8a2e777bbab198723ac7f/platform/platform-impl/src/com/intellij/ui/docking/impl/DockManagerImpl.kt#L224). Реализация для Qt использует [механизмы ADS](https://github.com/githubuser0xFFFF/Qt-Advanced-Docking-System/blob/023ce95934fecfd4cf5c672c9c404fabe0f54923/README.md), без копирования Java-компонентов.

`workspace_ide` проверяет отрыв вкладки, preview, Escape, независимые внешние окна, auto-hide, сохранение состояния и идентичность содержимого. `qt_workspace_resize_windows` проверяет правила переключения графиков в host. Offscreen-проверки не подтверждают нативное визуальное качество и поведение на нескольких мониторах с разным DPI.

При docking точные индикаторы сохраняют приоритет; дополнительно края области принимают сброс в полосе 22%, её центр создаёт вкладку. Для внешнего края контейнера полоса составляет 10%. Preview показывает результат до отпускания кнопки; Escape отменяет операцию. Поскольку ADS 5.1.1 не предоставляет переопределяемый hit-test, эта единственная правка исходников применяется проверяемым `cmake/patch_ads_drop_zones.cmake` к зафиксированной версии. При несовпадении исходников конфигурация останавливается. Захват OpenGL-снимка для preview отключён.

В редакторе потока данных обычное колесо мыши меняет масштаб вокруг указателя. Ctrl+колесо мыши двигает схему вертикально, Alt+колесо — горизонтально. Двухпальцевый свайп тачпада панорамирует одновременно по X/Y, pinch меняет масштаб (в Windows — Ctrl+wheel от тачпада). Windows-адаптер сохраняет MK_CONTROL из исходного wheel-сообщения (Qt может потерять этот признак pinch). Физическое колесо определяется по соответствующему пакету Raw Input; IMDT_MOUSE не используется как доказательство, поскольку Windows так маркирует и свайпы тачпада. Регистрация Raw Input сохраняет legacy-сообщения и не заменяет существующую регистрацию. Время и дельта связывают native и Qt события. Для остальных платформ используются Qt pointing device и pixel/phase/system-synthesized признаки. Старые драйверы, эмулирующие аппаратное колесо через Raw Input, могут остаться неразличимыми. Диагностика включается через QT_LOGGING_RULES=ui.input.wheel.debug=true. Инерционные события игнорируются. Запас 160 пикселей сохраняется по обеим осям, даже если схема помещается в viewport. Полосы прокрутки появляются при необходимости. Delete, Backspace и команда контекстного меню удаляют выбранные элементы через общий undo stack. Масштаб, упорядочивание и центровка располагаются справа перед размещением. Каждый активный заголовок графика показывает свой FPS, включая 0 при отсутствии обновлений; общая настройка FPS отключает эти отображения. Стрелочные индикаторы docking невидимы, preview области сохраняется.
