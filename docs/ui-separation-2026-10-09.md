# Разделение UI перед QML — 2026-10-09

Этот блок сохраняет Qt Widgets и текущее оформление. Он создаёт границы,
через которые представление можно заменить на QML, не перенося обработку
сигналов или сетевые клиенты в интерфейс.

## Результат

| Область | Ответственность после разделения |
| --- | --- |
| Параметры | `NodeParameterModel` описывает поля, значения, доступность, запросы редактирования и состояние ввода; не зависит от QWidget/QtNodes. |
| Представление параметров | `NodeParameterForm` создаёт Widgets. Инспектор и inline используют одну модель. `AudioNodeModel` связывает её с QtNodes и существующими операциями редактора. |
| Команды | `UiCommandRegistry` хранит стабильные ID, QAction, сочетания, контекст и доступность. Меню и кнопки используют общие действия. |
| Процессоры | `ProcessorDirectoryModel` хранит снимок и выбор; `ProcessorManagerDialog` и selector отображают его. `ProcessorDiscoveryPort` отделяет discovery от конкретного клиента. |
| Desktop composition | `CoreApplication` создаёт `ProcessorDiscoveryAdapter` и подключает существующий engine provider. `MainWindow` не создаёт AggregatorClient. |
| Общие контролы | `FieldRow`, `CollapsibleSection`, `ValidationMessage`, `SliderValueControl` дают общие подписи, помощь, ошибки и сброс; палитра наследуется от `ui::Theme`. |
| Сохранение | Типизированные scopes разделяют preferences, project presentation, session workspace и adapters. UI-дельта сохраняет существующий документ без извлечения draft и без Apply. |

Параметры обработки, контракты портов и настройки адаптера имеют явные секции
и стабильные ключи. Группировка по `objectName` удалена. Domain/application
операции продолжают проверять допустимость изменений; presentation metadata
не заменяет бизнес-валидацию. Переносимые domain/application/runtime не получили
зависимостей от Qt или Widgets.

Ошибочный и ещё неподтверждённый ввод переживает перестройку формы; допустимое
значение передаётся через существующие edit/Undo операции. Int64/UInt64 не проходят
через double. Раскрытие секций сохраняется по ID узла в памяти сеанса.

История схемы доступна в контексте редактора, включая меню, открытое из него.
Текстовый ввод, spinbox и диалоги исключены. Старые команды скрытых Network/WLED
страниц удалены; выходы настраиваются через узлы. Компактная кнопка Data Flow
поясняет действие в переводимой подсказке.

Пресеты содержат раскладку панелей, но не геометрию главного окна. Геометрия
остаётся в workspace состояния сеанса; геометрия из ранее сохранённого пресета
игнорируется без миграции или перезаписи пользовательского файла.

## Независимое ревью

A проверил B, B проверил C, C проверил A. Владельцы исправили потерю pending
input при rebuild, потерю editor-origin при QAction dispatch из popup,
сохранение workspace при закрытии окна через полный draft-save, потерю typed
itemData capture chooser и переполнение верхней панели на ширине 800 px.
Также исправлены запись при отключении autosave и потеря явного режима autosave,
когда исходный документ наследовал значение по умолчанию.
После исправлений исходники приняты в статическом scope. Автоматические
проверки интеграции выполняет координатор.

## Проверки и ограничения

Новые `ui_architecture_tests` проверяют fake discovery, жизненный цикл модели,
контекст команд и popup origin, общие поля/accessibility, скрытые страницы,
точность UInt64, ошибки и pending input, синхронизацию и раскрытие секций.
`ui_persistence_tests` проверяет независимое сохранение темы при несохранённом
draft, сохранность applied graph и границу геометрии пресета. Проверка
ConfigManager сохраняет preferences без draft, opaque unknown fields и
атомарность отказа при внешней смене версии.
Существующий shipped GUI probe дополнительно проверяет смену темы при
отклонённом processing draft: сохранённые draft/applied snapshots и работающая
схема остаются прежними. Включение UI-autosave и явный Save проекта проверяются
как отдельные действия.

Существующие editor/workspace/config проверки сохранены. Тестовые вызовы
команд получили необходимый активный контекст собственного offscreen-окна;
проверки удалённых команд заменены проверкой их отсутствия.

Итог: release build **PASS**, полный host CTest **100/100 PASS**
(39 UI сценариев), `git diff --check` PASS. Приёмка ограничена этим блоком
разделения UI; предыдущие core-fixes статусы не пересмотрены.

Итоговые результаты и evidence фиксируются в
[progress-checklist](refactoring/progress-checklist.md). Логи этого запуска:
`cmake-build-release/ui-separation-1791518587407`.

Нативная визуальная приёмка Windows/3D отдельно не проводилась. Offscreen
проверки не являются её заменой. QML, новые форматы хранения и DSP в этот блок
не входят. Инфраструктура help/units у descriptors готова; полные пояснения
для каждого поля ещё требуют отдельной продуктовой проработки.
