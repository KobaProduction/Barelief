# Музыкальный спектр и частотные профили

[Документация](../README.md) · [Графики](graphs.md) · [Runtime API](../reference/runtime-api.md)

Основной первый пример «Спектрограмма: генератор, loopback, микрофон» строит
независимые широкополосную и нотную спектрограммы, а затем общий ряд. Выбранные аудиоданные и Fs проходят через переключатель
и ресэмплер; размер готового окна измеряет ArrayLength. Генератор окна получает
числовой N, выдаёт w[n], сумму окна C=sum(w) и сумму квадратов E=sum(w²), а общий поэлементный умножитель
применяет w[n] к данным перед RealFourier.
В AmplitudePhase на карточке выбираются вид спектра и «Компенсация FFT и окна»;
отдельный N этому блоку не передаётся. Он вычисляет размер по длине двух
обязательных плоскостей Re/Im и явному формату спектра без DC.

После AmplitudePhase второй общий умножитель применяет независимый массив
коэффициентов коррекции. По умолчанию генератор массива выдаёт единицы;
его числовой размер берётся из Re FFT, амплитуды на него не подаются.
Загрузка статистически рассчитанных коэффициентов — отдельный следующий этап,
она не заменяется зависимым от значений спектра фиктивным профилем.

`BroadbandRow` сохраняет НЧ40…250Hz без редукции,
усредняет СЧ250…4000Hz до16 значений и берёт максимумы ВЧ4000…16000Hz
в8 группах. Параметры доступны в инспекторе: границы, число выходов и режим
каждой части; доступны среднее, RMS спектральных значений и взвешенное среднее.
`NoteSpectrum` отдельно настраивается и по умолчанию охватывает MIDI21…108, интерполируя значения
спектра на частотах нот. Это формула нотного ряда из
[авторской статьи](https://github.com/ArthurKoba/AI-Science/blob/main/articles/light-music/audio-spectrograms/article.md),
а не гармонический детектор нот. Точность интерполяции ограничена FFT и окном.

Каждый ряд подключён к своему накопителю. Оба получают явный числовой шаг
частоты от FrequencyStep: его входы — Fs ресэмплера и измеренный размер окна N.
ArrayConcat соединяет ряды для общего накопителя. Все четыре части
располагаются последовательно, поэтому общая ось индексная. На панели показаны диапазоны индексов НЧ/СЧ/ВЧ/нот;
нотный выход можно отдельно смотреть с реальными частотами Hz. Два числовых
выхода показывают взвешенное совпадение пиков с полной оценочной сеткой
(default MIDI0…127) и с выбранной частью. Изменение выходных нот не меняет
полную сетку оценки. Без пиков соответствующий процент недоступен;
это не вероятность музыки и не подтверждение распознавания мелодии.
Отрицательные и неконечные значения входного спектра отвергаются с диагностикой
у музыкального обработчика: нужно проверить коэффициенты коррекции и операцию
над массивами. Зависимые узлы получают недоступность результата, без повторения
исходной ошибки; следующий корректный кадр восстанавливает обработку.
Подробнее о формулах и ID — [Runtime API](../reference/runtime-api.md#независимые-спектральные-ряды).

Нотная ветвь стартовой схемы подключена к `PianoView`: клавиши и столбцы
показывают готовые значения нотного ряда. Распознавание и нормирование
выполняются в обработчиках, а не в графике. Первую MIDI-ноту задаёт обычный
UInt32-выход `NoteSpectrum` через явный вход представления. Поэтому изменение
диапазона нот сохраняет соответствие клавиш, а подпись частоты использует
фактические Hz-координаты ряда, включая выбранную настройку A4. Недоступные
данные очищают отображение; смена первой ноты очищает прежние значения.

DC Re/Im Fourier по умолчанию скрыты; их можно показать действием блока.
Подключённые DC остаются видимыми. Последний bin real FFT сохраняется.
Графики спектра и фазы получают одинаковый шаг Fs/N; самому FFT Fs не нужна.

В каталоге примеров есть отдельная схема «Музыкальный спектр: RFFT, профили
и нотная активность» (`music-research`). Она не заменяет стартовую схему или
сохранённый проект. После выбора примера используйте штатное «Сохранить как»,
чтобы сохранить параметры и расположение узлов в отдельный проект.

Схема выбирает один mono-поток генератора или системного звука. Затем выполняет
ресэмплинг, накопление окна, оконную функцию, RFFT и спектральную проекцию.
Частотный нормализатор питает две независимые ветви Float32: широкополосные признаки
и экспериментальную нотную активность. Их результаты (16 + 48 значений)
объединяются в одном ArrayConcat, после чего один SpectralQuantize
преобразует составной ряд в UInt8 перед History и общей спектрограммой.
Исходные признаки остаются доступны для диагностики без квантования.

Исследовательские начальные настройки: Fs после ресэмплинга 32768 Гц,
окно Hann 4096, анализ 60 кадров/с, 16 частотных полос,
48 нотных ячеек, единый History 512 × 64 в UInt8. Частота отрисовки
настраивается отдельно. При 60 Гц и Fs 32768 межкадровый шаг чередует
546/547 отсчётов на рациональной сетке; это не уменьшает FFT4096.
История охватывает 512/60 ≈ 8,53 с (временной диапазон между крайними
кадрами — 511/60 ≈ 8,52 с). Эти настройки не синхронизируют
независимые аппаратные часы.

## Спектральные значения

`RFFT` выдаёт одну Float32-матрицу `[N/2+1][2]`: оси `Bin` и `Component`,
компоненты Re=0 и Im=1. Это комплексные коэффициенты одного mono-потока,
включая DC и Nyquist. Прямой DFT не масштабирован; отдельный
`SpectrumProjection` получает выбранное представление без повторного FFT.

Пусть `X[k]` — DFT оконного сигнала, `S1=Σw[n]`, `S2=Σw[n]²`,
а `c[k]` равен 1 для DC/Nyquist и 2 внутри одностороннего спектра.

| Представление | Значение |
| --- | --- |
| Raw magnitude | `abs(X[k])` |
| Window-scaled magnitude | `abs(X[k]) / S1` |
| Peak amplitude | `c[k] * abs(X[k]) / S1` |
| RMS amplitude | `sqrt(c[k]) * abs(X[k]) / S1` |
| Power | `c[k] * abs(X[k])² / S1²` |
| PSD | `c[k] * abs(X[k])² / (Fs * S2)` |
| Bin power | `c[k] * abs(X[k])² / (N * S2)` |
| Phase | `atan2(Im, Re)`, радианы |

Логарифмическая шкала dB вычисляется только в renderer по линейным значениям:
для амплитуды `20 log10(value/reference)`, для Power/PSD — `10 log10(value/reference)`,
с отдельным floor отображения. В схеме эти значения не заменяют линейные данные.

Power содержит коррекцию суммы окна. Сумма значений Power зависит от
эквивалентной шумовой полосы окна и не равна автоматически среднему квадрату
исходного PCM. `Bin power = PSD * Fs/N`; сумма мощности бинов равна
`Σ(windowed_pcm²)/S2`. Это мощность, без дополнительной нормировки по времени
она не называется энергией. Для интегрируемой плотности мощности используйте PSD и шаг Hz.
Широкополосный RMS в текущем исследовательском тракте означает
`sqrt(sum(Power))`, тональную оконно-калиброванную оценку,
а не измеренную громкость или акустический уровень.
Raw complex сохраняется для независимых проекций.
Подробные определения, совместимые ключи, отключённая компенсация и дополнение
нулями описаны в [спектральных калибровках](../reference/spectral-projections.md).

Для RFFT доступны radix2 и radix4. Desktop поддерживает размеры 512–16384,
степени двойки. Выбор radix не обещает фиксированного ускорения.
Подготовленный RFFT упаковывает реальные отсчёты в комплексное преобразование
половинной длины и восстанавливает уникальные коэффициенты. Таблицы создаются
заранее; обычный путь без изменения масштаба не вызывает поэлементный `scalbn`.
Спектральная проекция вычисляет только выбранную величину: Power и PSD
не требуют промежуточного модуля или квадратного корня. Ошибка обработки
не публикует частично рассчитанный спектр.
Raw full-complex FFT и packed RFFT имеют одинаковый Re/Im-контракт;
реализации, жизненный цикл и отдельный FFT4096 benchmark описаны в
[справочнике FFT](../reference/fft.md).

## Ресэмплеры

| Режим | Назначение |
| --- | --- |
| Bypass | Исходная Fs без фильтрации |
| Existing FIR | КИХ полного качества с длиной под отношение Fs и интерполяцией фаз |
| Compact FIR | Короткий КИХ с меньшим банком фаз и отдельными границами качества |
| SpeexDSP | Настольный backend, качество 0–10 |
| IIR | Экспериментальный low-pass с рациональной интерполяцией |
| Linear | Диагностическая интерполяция с риском алиасинга при downsampling |

В меню примеров также доступно «Сравнение ресэмплеров». Оно обрабатывает
синтетические тоны без вывода на динамики и показывает время подготовки,
p50/p95 обработки 480 входных отсчётов и память объекта с буферами.
Это не измерение полного RSS приложения, драйвера или аппаратного аудиотракта.
Частотные и alias-проверки выполняет адресный `resampling_modes_tests`.

Временные метки относятся к сетке выходного сигнала; задержка содержимого
отдельно зависит от режима. Linear использует текущий и предыдущий отсчёт
на точной выходной сетке и ожидает поступления следующего входного отсчёта
для дробной позиции. Для IIR задержка фильтра зависит от частоты.
Число taps, память и номинальная задержка FIR зависят от отношения Fs.
Вычисления FIR выполняются в Float32, подготовка коэффициентов — в double.
Подробности сетки, фильтра и проверки качества — в [Resampling API](../reference/resampling.md).

## Полосы, ноты и хранение

`BroadbandFeatures` принимает линейный Power и пользовательские границы в Hz.
Операции: сумма bin power, среднее, квадратный корень суммы, максимум
и сумма положительных межкадровых изменений. Полосы полуоткрытые,
последняя включает верхнюю границу. Координаты — реальные центры полос.

`NoteSalience` задаётся первым MIDI-номером, количеством ячеек, A4 и числом
гармоник. Интерполяция локальных пиков и гармонический вклад дают
экспериментальную активность нотной сетки. Это не готовое распознавание нот,
аккордов, мелодии или музыкального ритма. Разрешение ограничено Fs, FFT и окном.

`SpectralQuantize` использует фиксированное отображение
`q=round(clamp((x-min)/(max-min),0,1)*(2^bits-1))`, bits 8 или 16.
Половины округляются вверх. Обратное значение:
`x=min+q*(max-min)/(2^bits-1)`. Значения вне диапазона насыщаются;
покадровой автоматической нормировки нет. Спектрограмма компактного History
показывает коды квантования. Исходные Float32-признаки доступны отдельными
выходами для диагностики. Единая UInt8-история 512×64 занимает 32768 байт значений (32 КиБ);
вариант основного графа 512×96 — 49152 байта (48 КиБ). В основном
графе это 48 широкополосных + 48 нотных значений, тогда как в
`music-research` — 16 + 48: эти два пресета имеют разную конфигурацию
признаков и не считаются взаимозаменяемыми только по типу UInt8.
Метаданные, рабочие буферы, графический интерфейс и служебная память
сюда не входят.

## Анализ файлов и профили

Диалог «Инструменты → Частотная статистика и профили» разделяет измерения,
исследование кривой и применение к графу. Музыка сканируется один раз;
изменение метода построения, отображения или целевого FFT не читает её повторно.

### Сканирование

По умолчанию каждый WAV/FLAC/MP3 анализируется на исходной Fs: FFT4096,
Hann, калиброванная пиковая амплитуда, 120 кадров/с. КИХ включается явно
селектором режима PCM; выходная Fs нужна только в этом режиме. При КИХ
достоверная полоса ограничивается 0,40 × min(Fs исходной, Fs анализа).
Повышение Fs не создаёт новых измеренных частот.

FFT, окно, каналы, темп/шаг анализа и ресэмплинг принадлежат снимку сканирования.
Их изменение относится к новому прогону и не меняет уже полученные результаты.
Отменённый или неудачный новый прогон сохраняет предыдущие результаты.
Дополнительные параметры потоков и уменьшенных спектрограмм свёрнуты.

Для каждого трека сохраняются исходная и фактическая Fs, размер FFT,
средние и частотные максимумы, граница измеренного диапазона, показатели
тишины и занятые группы PCM RMS с шагом 2 дБ. Исключаются только точно
нулевые окна; тихие ненулевые сигналы остаются в основных измерениях.
Полные спектры каждого временного кадра не сохраняются. Поэтому из файла
нельзя восстановить произвольные временные границы тихого фрагмента или
произвольно повысить разрешение уменьшенной спектрограммы.

Основные спектры имеют float64, спектры RMS-групп — float32. Средний квадрат
модуля не собирается: точные средние Power/PSD нельзя получить возведением
средней амплитуды в квадрат. В просмотре трека можно переключить калиброванную
амплитуду на модуль FFT через сохранённую калибровку. Это не новый FFT.

Обработка использует общие PreparedResampler, RFFT и SpectrumProjection;
масштабирование live DSP сохранено. Первые окна дополняются нулями,
EOF не создаёт дополнительных спектральных кадров. Fs, кадры анализа в секунду
и частота отрисовки — независимые величины.

### Исследование и построение

После сканирования или загрузки `.brscan` диалог автоматически строит кривую.
Слева выбирается трек для просмотра; его флажок отдельно управляет участием
в корпусе. Справа находятся методы и ограничения, в центре — исходные
измерения, обе аппроксимации и коэффициенты усиления.
В списке треков видны состояние, длительность и исходная/фактическая Fs.

Объединение использует упорядоченное объединение частотных точек треков
в реальных Гц. Вклад трека интерполируется только внутри его достоверной
полосы. На каждой частоте показано число участвующих треков; отсутствующие
измерения не считаются нулевыми. Общей пользовательской Fs измерений нет.

Основной метод — среднее частотных максимумов отдельных композиций с равным
весом треков. Для сравнения доступны глобальный максимум и верхний процентиль.
Процентиль использует эмпирический индекс `floor(q*(n-1))`; при малом числе
треков его оценка ступенчатая. Полином Чебышёва и кусочная кубическая функция
работают с логарифмом амплитуды в линейных Гц. Частотные веса предотвращают
случайное увеличение влияния плотных участков объединённой сетки.

Изменение параметров автоматически обновляет расчёт с короткой задержкой.
Объединение, аппроксимации и усиление кешируются отдельно. Пока результат
обновляется, сохранить или применить его нельзя; устаревшее фоновое задание
не заменяет более новое. Пересчёт не блокирует обработку графа.
Выбор уже рассчитанной аппроксимации переключает результат сразу.

Порог тихих кадров расположен в просмотре трека. Он объединяет сохранённые
RMS-группы с весом по числу кадров и не меняет основную кривую. Нижняя группа
включает ненулевые RMS ≤ −200 дБ, отдельная верхняя — RMS > 0 дБ.
Изменение порога не читает музыку. RMS сам по себе не отделяет тихую музыку
от аналогового шума.

Отображение имеет отдельные границы дБ, опорное значение, автомасштаб,
сетку, курсор и масштабирование. Логарифмическая частотная ось меняет только
отображение. DC показывается отдельно. Прогноз спектра после коррекции
рассчитывается по статистике и не выдаётся за повторный прогон аудио.
Обновление шкалы, подписей и рядов публикует одно итоговое изображение.
Геометрия строится только для видимого диапазона с соседними точками на границах;
в каждом пиксельном столбце сохраняются первая, последняя и обе крайние точки
в исходном порядке. Пропуски не соединяются линией. Исходные измерения,
аппроксимация и значения под курсором не прореживаются. Автодиапазон Y
кешируется до изменения данных или шкалы.

### Коэффициенты и применение

Усиление ориентировано на амплитуду 1 и ограничено диапазоном от 1 до
выбранного максимума. По умолчанию максимум ×100 (+40 дБ), регуляризация
−120 дБFS. Для измерения `a`, аппроксимации `s`, абсолютного уровня `e`
и ограничения `M` используется непрерывная формула:

```
confidence = a² / (a² + e²)
gain = 1 + confidence * (clamp(1 / hypot(s, e), 1, M) - 1)
```

Нулевые измерения и внешние диапазоны получают единицу; на краях действует
плавный переход в Гц. Нет переключения коэффициентов на −120 дБ и
экстраполяции отсутствующих данных. Это частотная коррекция, а не измерение
или физическое выравнивание громкости. На графике усиление показано в дБ,
с линиями 0 дБ и предела; сохраняемые коэффициенты остаются линейными.
Опорное значение отображения новой функции не меняет её усиление.

Карточка применения находится рядом с настройками кривой. Она показывает
объявленный маршрут `ArrayFill → ArrayMultiply`, текущие Fs/FFT и причину
несовместимости. Коэффициенты вычисляются на `k*Fs/N` текущего графа,
без ресканирования. Проверяются калиброванная пиковая амплитуда, окно,
каналы и layout; Power/PSD не получают амплитудные коэффициенты молча.
Сам граф меняется только действием «Применить», одной Undo/Redo-транзакцией.
Фаза, связи, положение узлов и DSP-тракт сохраняются.

Проект хранит рассчитанный массив. После изменения его Fs/FFT сохранённую
функцию применяют повторно; массив не является постоянной привязкой к функции.
Карточка показывает, применён ли текущий результат, и явно требует повторного
применения после изменения кривой, маршрута или сетки графа.
Новые профили строятся по максимумам. Старые профили выравнивания среднего
спектра загружаются и применяются с прежними ограничениями frontend.

### Документы и совместимость

После загрузки или сохранения показаны имя и фактический размер файла;
полный путь и формат доступны при наведении. Настроек архиватора нет.

`.brscan` v3 хранит измерения на сетках отдельных треков, настройки сканера,
RMS-группы и уменьшенные спектрограммы. Готовой функции и целевых коэффициентов
в нём нет. `.brprofile` v6 содержит функцию v2, явную ось Гц, данные
регуляризации, покрытие и ограничения. Треки, RMS-группы, спектрограммы и
целевой массив коэффициентов в новый готовый профиль не записываются.
Массив для текущей схемы вычисляется при применении.

Сканирования v1/v2 и профили v3/v4/v5 продолжают читаться. Функции v1 сохраняют
прежнюю интерпретацию reference и своей частотной сетки. Профиль без функции
требует точного совпадения frontend; отсутствующая статистика не выдумывается.
Без сохранённой спектрограммы выбор трека не запускает скрытый прогон аудио.
Повреждённый файл отклоняется до замены текущего документа.

### Формат файлов сканирования и профиля

Диалог сохраняет результаты в `.brscan`, готовую функцию — в `.brprofile`.
Это ZIP-контейнеры без внешнего сжатия (Store): `manifest.json` описывает
содержимое, а `arrays/` содержит сжатые бинарные числовые блоки `.b2`.
Библиотеки miniz и C-Blosc2 связаны с desktop adapter статически; Python
и внешние архиваторы при работе приложения не требуются.

Контейнер `barelief.music_archive` v1 задаёт `content` (`scan` или `profile`),
профиль `blosc2-zstd5-shuffle-v1`, вложенный `document` и список `blocks`.
Внутренние документы сохраняют свои версии и ключи. Дескриптор блока задаёт
`entry`, `dtype` (`float32_le`/`float64_le`), `shape`, число `bytes` и SHA-256
несжатых данных. Ссылки на массивы содержат `encoding: blosc2-le`, `entry`,
`offset` в элементах и `count`. Средние и пиковые RMS-спектры объединены
по треку в две матрицы `[RMS-группа][FFT-бин]`; ссылки выбирают их строки.
Координаты времени/частоты и спектрограммы также сохраняются численно.
JPEG и сокращение точности не применяются.

Архивный reader проверяет ZIP CRC, SHA-256, dtype, размеры, срезы и известные
lossless-фильтры до публикации результата. Неизвестная версия, другой тип
документа, отсутствующие/дублирующиеся/лишние записи и повреждённые блоки
отклоняются атомарно. Файлы из ZIP не извлекаются на диск. Ограничения:
архив и суммарные распакованные массивы — до 1 ГиБ, manifest — до 64 МиБ,
отдельный массив — до 64 МиБ, до 50 000 записей. Кеш строк RMS-матриц
ограничен 32 МиБ. Известные поля обновляются поверх сохранённых расширений
manifest, документа, ссылок и дескрипторов блоков.

Запись использует `QSaveFile` без прямого перезаписывания исходного файла:
ошибка валидации/записи сохраняет предыдущую версию. Старые JSON сканирований
v1/v2 и профилей v3/v4/v5 загружаются по содержимому; расширение имени
не определяет способ чтения. Явный путь `.json` в программном API оставляет
JSON-экспорт для существующих интеграций. Новые файловые диалоги по умолчанию
предлагают архивный формат. Текущий диалог загружает документ целиком;
разбиение на блоки пока не означает ленивую загрузку треков в интерфейсе.
