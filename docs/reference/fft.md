# FFT: вещественные и комплексные входы

`dsp_kernels::FFT::process_complex(real, imaginary, output)` принимает две
Float32-плоскости по N значений и выдаёт полный ненормированный спектр:
N чередующихся пар Re/Im, всего 2N float. Отрицательные частоты самостоятельны;
мнимые DC и центральный коэффициент не зануляются. Fs этому API не требуется.
Radix-2 поддерживает степени двойки, radix-4 — степени четырёх в бюджете сборки.
Метод использует тот же подготовленный scratch и backend, что real-вход класса
`FFT`; дополнительного рабочего буфера и повторного FFT нет.
Ошибки размера, NaN/Inf и непредставимого результата сохраняют caller output.

В редакторе эти входы представлены разными блоками `Fourier` и `RealFourier`.
У первого два входа Re/Im, у второго только вещественный вход. Четыре числовых
выхода: Re и Im ненулевых частот, затем отдельные raw DC Re и DC Im scalar.
Комплексный блок сохраняет k=1…N−1; вещественный — k=1…N/2 включительно.
Таким образом, при N4096 вещественные массивы содержат 2048 значений и
сохраняют конечную точку Найквиста. Коэффициенты не нормированы; raw DC не
следует подписывать как среднее исходного сигнала после применения окна.
Частотная ось не создаётся этими блоками. Происхождение и время входного
пакета сохраняются отдельно от численных значений.

`ComplexPolar` принимает Re и Im и выдаёт обычные числовые модуль и фазу
(радианы). Модуль не является автоматически калиброванной peak amplitude;
нормировка размера/окна и одностороннего спектра выполняется отдельно.
Обработка двух входов использует подготовленные владеющие буферы и сопоставляет
интервалы, эпохи и поколения: Re одного кадра не объединяется с Im другого.
Для ComplexPolar и AmplitudePhase обязательны оба подключения Re/Im:
отсутствующая плоскость делает оба выхода недоступными, не подменяется нулём.
У комплексного Fourier отключённый вход по-прежнему задаёт типизированный ноль.
Эти численные графовые операции не требуют `music_enabled`. Доступный размер
ограничен compiled FFT capacity и лимитами выбранного runtime-профиля;
аппаратная приёмка ядра не заменяет проверку графовой интеграции.

## Амплитуда и фаза спектра

`AmplitudePhase` принимает тот же явный формат без DC: параметр
`positive_half` выбирает k=1…N/2 с Найквистом либо полный k=1…N−1.
При длине плоскости M размер FFT вычисляется как 2M либо M+1 соответственно.
Отдельного порта N нет; скрытые метаданные производителя не используются.
Исторический ключ `fft_size` сохранён в формате, но не управляет вычислением
и не показывается как редактируемая настройка этой операции.

Общий переключатель «Компенсация FFT и окна» (`normalize`) включает поправки
выбранного представления, без приведения пика кадра к единице.
Окно явно передаёт C=sum(w) и E=sum(w²) через Float64-порты; при включении
модуль равен abs(X)/C, peak amplitude — d*abs(X)/C, спектр мощности —
d*abs(X)²/C², PSD — d*abs(X)²/(Fs*E). Для положительной половины d=2,
кроме последнего Найквиста, где d=1; для полного спектра d=1.
При выключении первые два режима выдают abs(X), последние два — abs(X)².
Ненормированный квадрат модуля не подписывается как PSD на герц.
Фаза не меняется переключателем. Поправки рассчитаны для ненормированного
прямого DFT; восстановление peak amplitude тона требует оговорки о биновой
частоте и спектральной утечке. Нормировка не делит кадр на его максимум.

## Существующие real-входы численных планов

Переносимые `dsp_kernels::FFT` и `dsp_kernels::PreparedRfft` принимают уже
оконные вещественные Float32-отсчёты. Окно, преобразование Int16/Int32 PCM,
модуль, фаза, power, PSD и нормировка уровня выполняются отдельно.

Оба real-входа вычисляют ненормированное прямое ДПФ с отрицательным знаком экспоненты.
Для N=4096 выход содержит 2049 пар `{Re, Im}` в естественном порядке,
то есть 4098 float. DC и Nyquist включены, их Im равен нулю. Выход не делится
на N и положительные частоты не удваиваются. При необходимости последующих
DSP-операций исходные Re/Im сохраняются.

| План | Вычисление |
| --- | --- |
| `FFT`, radix2 | Complex FFT(N) с нулевой мнимой частью входа |
| `FFT`, radix4 | Complex FFT(N), N должен быть степенью четырёх |
| `PreparedRfft`, radix2 | Упаковка real-входа → Complex FFT(N/2) → real split |
| `PreparedRfft`, radix4 | При N4096: два Complex FFT1024 → mixed-radix/real reconstruction (слитая на optimized ESP32) |

```cpp
dsp_kernels::PreparedRfft plan;
if (!plan.prepare(4096, true)) { /* preparation failure */ }
// windowed: 4096 float; complex_output: 4098 float, allocated by the caller.
if (!plan.process(windowed, complex_output)) { /* output remains unchanged */ }
plan.reset(); // Release instance storage; disables processing.
```

Опциональная структура копируется при подготовке. Без неё включается максимум
оптимизаций, доступный в данной сборке:

```cpp
dsp_kernels::PreparedRfft::Options options;
options.platform_optimizations = false; // SDK complex kernels + scalar split.
plan.prepare(4096, true, dsp_kernels::PreparedRfft::Split::Automatic, &options);
```

Это выбор выполнения отдельного плана. Он не освобождает размещённый код IRAM.
Для экономии кода firmware composition предоставляет два независимых флага:
`PORTABLE_SDK_PLATFORM_RFFT=OFF` исключает все дополнительные Xtensa RFFT kernels;
`PORTABLE_SDK_RFFT_EXTRA_OPTIMIZATIONS=OFF` исключает contiguous copy/max и
специализированный radix2 kernel, сохраняя radix4/fused reconstruction.
Оба флага по умолчанию ON. Численный контракт и проверки одинаковы во всех режимах.

`FFT` имеет такой же набор `prepare/process/reset/samples/bins/workspace_bytes`.
Можно заменить план, не меняя оконный PCM и представление комплексного выхода.
Подготовка выделяет выровненные на 16 байт буферы; обработка память не выделяет.
Входные и выходные буферы вызывающего кода не требуют этого выравнивания.
Один mutable-план принадлежит одному потоку. Ошибка подготовки отключает план;
ошибка обработки не публикует частичный результат.
Отказ выделения instance storage возвращает `false` из `prepare()` и отключает
обработку. `reset()` освобождает в том числе частично подготовленные buffers.
ESP-IDF composition выбирает выравнивание поверх C allocation с проверкой NULL:
в exception-free runtime aligned `nothrow new` может вызвать throwing new и abort.
Буферы сохраняют16-byte alignment; allocation и её metadata не входят в hot path.

Обычный PCM обрабатывается без изменения масштаба. Для больших конечных Float32
входной блок временно уменьшается степенью двойки, результат восстанавливается
перед публикацией. Запас до переполнения оставлен для промежуточных бабочек и split.
NaN/Inf и непредставимый в Float32 raw-результат отвергаются. Нормировка графика
и компенсация окна не входят в эту защиту. Субнормальные значения обрабатываются
с ограничениями арифметики и настроек FPU целевой платформы.

## Реализации и спектральные потребители

`PreparedRfft::Split::Automatic` использует SSE2 real split на x86-сборке с SSE2,
ae32/aes3 real split в optimized ESP-IDF composition для ESP32/ESP32-S3
и Float32 scalar fallback на остальных платформах. `Split::Scalar` позволяет
отдельно проверить скалярный split. `split_implementation()` сообщает выбор.
Глобальные fast-math/AVX-флаги не требуются. Float32 split и mixed butterfly
проверяются против независимого double DFT, включая комплексную фазовую информацию.

Полный FFT backend `ESP_DSP` вызывает SDK dispatch и для radix2, и для radix4. Конкретную
ANSI/ae32/aes3/arp4 реализацию выбирают заголовки установленного SDK по SoC и
`CONFIG_DSP_OPTIMIZED`. В ESP-DSP 1.8.2 классический ESP32 имеет ae32, S3 — aes3.
S3 float-ядро использует FPU, аппаратные циклы, парные загрузки и multiply-add;
его нельзя описывать как SIMD-арифметику Float32 только по наличию инструкции
загрузки нескольких значений. Классический ESP32 также не имеет SSE2 или S3 ISA.
Его дополнительные LX6-ядра подключаются только при `CONFIG_IDF_TARGET_ESP32`
и `CONFIG_DSP_OPTIMIZED`: упаковка, mixed-radix butterfly и automatic real split
используют FPU и аппаратные циклы, критический assembler размещён в IRAM.
Это скалярная Float32 арифметика с планированием независимых операций, не SIMD.
На ESP32-S3 подключаются отдельные адаптации SDK aes3 half/quarter FFT с
парными 64-битными `ee.ldf.64.ip` / `ee.stf.64.ip` и exact unity stages.
Real reconstruction использует общие LX6/LX7 Float32 FPU kernels и аппаратные
циклы; split сообщает `aes3-f32` или `aes3-fused-f32`.
Парная загрузка Float32 не является SIMD Float32 арифметикой.
На S3 real split, fused reconstruction и последняя unity-стадия radix4 также
загружают и записывают Re/Im парными инструкциями с продвижением указателя.
Это сокращает memory/address instructions; последовательность арифметических
Float32 операций и коэффициенты сохраняются. Парные обращения ограничены
внутренними выровненными buffers/twiddles; caller buffers по-прежнему могут
иметь обычное Float32 выравнивание. Путь классического ESP32 не меняется.

Для mixed-radix случая optimized ESP32 `Automatic` по умолчанию использует
fused real radix4 reconstruction (`ae32-fused-f32`). Четыре выходных bins
`k`, `N/4-k`, `N/2-k`, `N/4+k` вычисляются вместе с тремя комплексными
ротациями вместо четырёх и без промежуточной записи complex FFT(N/2).
Множители 1/2 поглощены в подготовленную таблицу twiddles; нормировка raw-выхода
не меняется. DC, Nyquist и самосопряжённые bins вычисляются отдельно.
Проверка входа и even/odd упаковка объединены в один проход; при необходимости
большой вход масштабируется в приватном буфере до FFT. Атомарность ошибок
и конечность выходов по-прежнему проверяются до публикации.

Half/quarter FFT внутри RFFT использует адаптации ESP-DSP ae32/aes3 (Apache-2.0).
В radix2 группы с коэффициентами `1+0i` (вся первая стадия и группа `j=0`
последующих стадий) выполняют точные суммы/разности без комплексных умножений.
Указатели продвигаются инструкциями записи с post-increment;
вычисление адресов вынесено из внутренней бабочки. Последняя стадия `N2=1`
использует один аппаратный цикл по соседним complex-парам и коэффициентам,
без настройки отдельного одноэлементного цикла для каждой бабочки.
Это специализация фиксированной геометрии FFT, не содержимого сигнала.
В radix4 последняя
стадия с коэффициентами `1+0i` выполняется без их загрузки и умножений.
Эти kernels размещены в IRAM. Radix4 kernel используется также при N512/2048
с complex FFT256/1024, где mixed-radix decomposition не требуется.
Полный FFT продолжает вызывать штатное SDK-ядро.
Дополнительных instance buffers/twiddle tables не выделяется; расход IRAM
нужно учитывать отдельно от `workspace_bytes()`.
Для RFFT без mixed-radix decomposition finite/max classification объединена
с копированием real-пар в приватный буфер: 16 слов за итерацию и хвост по четыре.
Если требуется защита большого конечного входа, масштабируется уже приватная
копия. Невалидный вход никогда не публикуется в caller output.
Опция composition `PORTABLE_SDK_FUSED_RFFT=OFF` отключает fused reconstruction
и объединённую проверку/упаковку для A/B; quarter kernel остаётся тем же.
`Split::Scalar` также сохраняет раздельные butterfly/split. Публичный API
и автоматический SSE2-путь на ПК остаются прежними.

Алгебра fused reconstruction: `H=N/4`, `M=N/2`, `j=H-k`,
`W=exp(-2*pi*i/N)`. `E` и `O` — два Complex FFT(H) результата.
Для `1 <= k < H/2` определены:

```text
A = (Re E[k] + Re E[j])/2       B = (Im E[k] - Im E[j])/2
C+iD = (Im E[k]+Im E[j]) + i*(Re E[j]-Re E[k])
U+iV = (Re O[k]+Re O[j]) + i*(Im O[k]-Im O[j])
S+iT = (Im O[k]+Im O[j]) + i*(Re O[j]-Re O[k])
R+iI = (W^(2k)/2)*(U+iV)
L+iQ = (W^k/2)*(C+iD)
P+iZ = (W^(3k)/2)*(S+iT)
X[k]   = (A+R+L+P) + i*( B+I+Q+Z)
X[M-k] = (A+R-L-P) + i*(-B-I+Q+Z)
X[j]   = (A-R-Q+Z) + i*(-B+I-L+P)
X[M-j] = (A-R+Q-Z) + i*( B-I-L+P)
```

Это алгебраическая перегруппировка mixed butterfly и real split, а не
приближение ДПФ. Float32 округления могут различаться. Portable helper
проверяется против полного double DFT в host-тестах; LX6-ядро — в firmware
correctness checks. Таблица `W/2` использует ту же quadrant symmetry;
дополнительные коэффициенты для `W^(3k)` не выделяются.

Проверка конечности и максимального модуля использует IEEE Float32 exponent bits;
развёрнутый проход LX6 обрабатывает четыре слова за итерацию. Копирование между
заведомо непересекающимися caller/instance buffers на Xtensa также развёрнуто
по четыре слова, минуя generic memmove. Проверки NaN/Inf, защита от переполнения,
атомарность отказов и субнормальные входы сохраняются. Radix2 backend ESP-DSP
использует `dsps_bit_rev2r_fc32`: lookup permutation для поддерживаемых размеров
и SDK direct fallback для остальных. Публичный raw FFT контракт не меняется.

`SpectrumProjection` — отдельная операция над raw Re/Im. Существующие узлы
с выходом N/2 `abs(X)/N` используют явно названный `MagnitudeSpectrum`;
этот составной обработчик не является raw FFT API. Старый desktop wrapper
`FFT2R/FFT4R/FHT2R/FHT4R` удалён: он не предоставлял самостоятельные FHT-ядра.

`reset()` освобождает только instance buffers. Общие SDK-таблицы сохраняются:
нельзя вызывать vendor deinit, пока ими пользуются другие prepared plans.
Внешний владелец освобождает общие таблицы после завершения всех пользователей.

Для native complex FFT4 длины N SDK требует **4*N float** коэффициентов
(16*N bytes), а complex data занимает **2*N float**. Параметр SDK table size
не является количеством байт. При N4096 twiddles занимают65536 bytes,
RAM bit-reversal lookup ещё8064 bytes; общий radix4 table budget —73600 bytes.
Его нельзя путать с instance workspace и IRAM-кодом.

В pinned ESP-DSP1.8.2 обнаружен failure-path дефект: отказ выделения bit-reversal
table после успешного выделения twiddles оставляет частичное состояние.
Прямой retry init с большим N может переиспользовать слишком маленький block.
Наш backend откатывает неудачную транзакцию через vendor deinit и обнуляет
pointer/capacity. Уже initialized tables не изменяются; undersized external
tables отвергаются без resize/deinit. Regression и воспроизводитель описаны
в [issue11](https://github.com/KobaProduction/Barelief/issues/11).
Прямое использование vendor API требует отдельного контроля lifecycle.

## Короткие проверки

```powershell
cmake --build --preset release --target rfft_tests esp_dsp_dispatch_tests
./cmake-build-release/bin/rfft_tests.exe --benchmark-only
ctest --preset release -R '^(rfft_tests|esp_dsp_dispatch_tests)$'
```

Benchmark измеряет только N4096: оконный Float32 PCM → raw Re/Im, включая
валидацию, упаковку, перестановку, split и публикацию. Шесть маршрутов:
full complex radix2/4 и real radix2/4 со scalar/automatic split. Используются
восемь окон семитонального сигнала с разными фазами, прогрев и чередование
маршрутов. Один замер содержит 32 вызова; p50 и `p95_batch_mean_us` относятся
к среднему времени вызова в пакете, не к индивидуальной хвостовой задержке.
Выделение памяти контролируется, включая aligned new.

Для диапазона 512, 1024, 2048, 4096, 8192, 16384 есть отдельный host target:

```powershell
cmake --build --preset release --target fft_size_benchmark
./cmake-build-release/bin/fft_size_benchmark.exe
```

Он компилирует те же production FFT sources и ANSI ESP-DSP в изолированный
профиль ёмкостью 16384, не меняя лимиты приложения и прошивки. CSV содержит
все шесть маршрутов, p50, p95 средних пакетов из 32 вызовов, instance workspace,
разницу с CFFT2, ошибку CFFT2 против прямого double DFT на 16 выбранных bins
и число allocation. В каждом размере 160 пакетов на маршрут и восемь входных
кадров; проверка между маршрутами охватывает все выходные коэффициенты.
Допуск: `0.0003 * max(1, N/4096) + 5e-6 * abs(reference)`.
Full radix4 для 512/2048/8192 помечается unsupported.
В профиле 16384 vendor выполняет прямую перестановку для размеров, для которых
нет готовой bit-reversal таблицы (свыше 4096). Instance workspace не включает
общие таблицы, входы и выходы вызывающего кода.

Полный тест дополнительно сравнивает оба raw FFT с прямым O(N²) DFT для
нескольких размеров и четырёх окон, проверяет DC/Nyquist, extreme/subnormal,
атомарность ошибок, reset/reprepare и отдельные спектральные проекции.
Host stub проверяет использование SDK dispatch и передачу отказов;
он не доказывает работоспособность assembler-кода на плате.

## Стенд ESP32 / ESP32-S3

[examples/esp32_fft_benchmark](../../examples/esp32_fft_benchmark/CMakeLists.txt)
собирается существующим ESP-IDF с внешним компонентом ESP-DSP и BDSP.
Ничего не устанавливается автоматически. Требуются `ESP_DSP_SOURCE_DIR`
и `BDSP_SOURCE_DIR`; выбор SoC выполняется стандартным `idf.py set-target`.
Build directory размещайте внутри `cmake-build-release`.

Стенд выполняет конечный набор CFFT2/CFFT4/RFFT2/RFFT4 для N512/1024/2048/4096, держит один
план за раз и выводит raw numerical difference, времена пакетов и heap counters.
Штатный CFFT4 для N512/2048 явно помечается unsupported: размер должен быть
степенью четырёх. Подстановка другого radix или zero-padding не выполняется.
RFFT дополнительно измеряется с scalar split. Перед timing он проверяет на плате
три фазы, размеры 8/16/32/64/512/1024/2048/4096, direct double DFT (все bins до 64,
16 выбранных bins для больших размеров), offset caller buffers, DC/Nyquist,
NaN/Inf, subnormal impulse, большой представимый impulse и атомарный overflow.
Максимальный допуск остаётся `0.0003 + 5e-6 * abs(reference)`.
Проверяются оба значения `Options::platform_optimizations` и scalar/automatic split.
Перед numerical/timing выполняются20 vendor init/deinit циклов с guarded external
tables/data и768 real преобразований (ноль, смещённый импульс, DC, Nyquist,
семь тонов, детерминированный шум), повторные prepare/reset, canaries и heap
integrity. Параллельная задача создаёт нагрузку на allocator; проверяется
восстановление свободной памяти после teardown. Это не сетевой/WiFi тест.
Все остальные компоненты больших размеров сравниваются с CFFT2 той же сборки.
Для каждого маршрута используются 24 прогревочных вызова и 96 пакетов
по 8 преобразований; p50 и p95 — квантили средних времён одного преобразования
в пакете. Это не p95 индивидуальной задержки. Окно Hann и семитональный вход
готовятся до измерения. Timing охватывает весь `process()` от оконного PCM до
публикации raw Re/Im, включая проверки, упаковку, перестановку и real split.
Маршруты идут в фиксированном порядке; завершённый прогон можно повторить
сбросом той же прошивки. Между пакетами задача уступает CPU.
`workspace_bytes()` не включает общие SDK-таблицы, caller buffers, стек и IRAM.
Heap counters отражают весь benchmark, а не изолированную стоимость плана.
Перед timing также принудительно создаётся недостаток contiguous heap: проверяются
отказ `prepare()`, неизменённый caller output, освобождение резервов и успешный retry.
Поэтому global minimum-free-heap включает искусственное исчерпание памяти;
для обычного working set используйте per-route free heap и явный memory ledger.
Результаты платы оцениваются отдельно от
host-тестов; компиляция без запуска не подтверждает аппаратную производительность.
Этот стенд не включает доставку PCM от I²S/BT, History или renderer спектрограммы.
`FFT_MEMORY_ONLY=ON` запускает memory/numerical diagnostics без timing sweep.

`sdkconfig.defaults` включает `CONFIG_DSP_OPTIMIZED`; для отдельной ANSI-сборки
задайте `SDKCONFIG_DEFAULTS` равным `sdkconfig.ansi.defaults` и используйте другой
build directory и собственный `SDKCONFIG`. Сравнивайте прошивки на одной плате
с одинаковой CPU frequency; стенд выводит target, frequency и optimized flag.

Опция CMake `FFT_STAGE_PROFILE=ON` включает внутренние cycle counters для input,
packing, complex kernel, permutation, mixed butterfly, real split, output
validation и publication. Clock/collector реализованы в benchmark composition;
переносимое ядро не зависит от ESP-IDF timers. Отчёт показывает среднее время
этапов; instrumentation и layout могут влиять на суммарное время. Окончательные
скорости измеряйте отдельной сборкой с `FFT_STAGE_PROFILE=OFF` (default).

## Экспериментальный Q15 FFT/IFFT

[gmf_fft_benchmark](../../examples/gmf_fft_benchmark/README.md) отдельно собирает
закреплённый Apache-2.0 компонент Espressif GMF FFT и сравнивает его обычный Q15
и HP forward/inverse с production `PreparedRfft` radix2/4 на Windows, ESP32
и ESP32-S3. Зависимость предоставляется явно и проверяется по SHA256;
в переносимые SDK targets и runtime graph она не добавляется.

Стенд сохраняет комплексный спектр и учитывает масштаб без подгонки gain.
Обычный inverse имеет round-trip gain `4/N`; HP использует показатель блока,
который текущий upstream хранит внутри handle. Для проверки стенд читает этот
показатель через отдельный probe в translation unit закреплённого исходника.
Это исследовательский интерфейс, не production-контракт SDK.

Базовый режим измеряет 512/1024/2048/4096, native Q15 / Float32 Re/Im,
память плана и caller buffers, forward error, round-trip и слабые тоны.
`GMF_EXTENDED_SWEEP=ON` добавляет FFT2R/FFT4R, размеры8192/16384 и
экспериментальные GMF2R / mixed GMF4R в режимах Q15 и HP. Stock GMF ограничен8192;
расширение16384 относится только к адаптированным кандидатам. Радикс-2
сохраняет integer-результат; у radix-4 иной порядок округления, его точность
и скорость оцениваются отдельно. Переносимый radix-4 не заявляется SIMD-кернелом.
Его комплексные произведения используют общую для Re/Im проверку узкого
диапазона и общие quotient/remainder части широкого пути, сохраняя округление
и насыщение. Portable HP R4 останавливает выбор stage shift при peak>=23169:
shift3 уже максимален для int16; меньшие peaks сканируются полностью.
HP pair helpers inline позволяют исключить промежуточные вызовы при публикации.
Это C-оптимизации, применимые и к обычному ESP32; выигрыш проверяется на target.
HP2 сохраняет forward/inverse/exponent побитово: portable Q14-products сужены
по доказанной границе, threshold scan завершается при достижении исходного порога;
S3 сохраняет upstream PIE. HP4 использует адаптивный BFP по стадиям и двухпроходный
wide Hermitian pack/unpack с единым сдвигом, без дополнительного heap scratch.
Его округление отличается от HP2; отдельный тест проверяет all-bin double FFT,
round-trip и inverse DFT произвольного Hermitian спектра, включая16384.
Экспериментальный `GMF_R4_S3_SIMD` добавляет S3 PIE batch-бабочки и wide real split
для Q15/HP; по умолчанию выключен до аппаратной приёмки. Разложение широкого
произведения сохраняет точные C R4 округление/насыщение и HP exponent; host-модель
проверяется отдельно от исполнения ASM. Перед timing прошивка сверяет реальные
PIE-выходы с моделью и guards, а CFFT/real split — побитово с C R4, включая HP exponent.
SIMD-константы требуют явного16-байтного выравнивания в итоговом ELF.
Проверенный signed16 fast path сохраняет полное произведение через high/low CMUL;
при нулевом округлении и сдвиге>=15 граница Q14 допускает прямой CMUL.
Более широкие данные сохраняют точное разложение без раннего сужения.
Batch повторно использует четыре входа и wide sums; малые стадии исключают
вызовы memcpy для отдельных complex значений, unity radix-2 tail векторизован.
Обход disjoint boxes для одного twiddle выполняется внутри ASM с приватной
копией контекста, включая small8; per-stage shift и caller context сохраняются.
Real split читает native пары напрямую, векторно квантует и публикует результат;
первый HP-проход только находит extrema для прежнего общего сдвига.
Квантизация и публикация объединены с вычислением пары: wide выходы остаются
в регистрах без промежуточного64-байтного output tile.
Экспериментальный `GMF_S3_VECTOR_PERMUTATION` отдельно включает точную SIMD
перестановку для адаптированных S3 Q15/HP R2/R4 при complex N>1024.
Она обращает16 бит восьми индексов через masked SWAR, затем сохраняет log2N бит;
indexed32-bit transfers перемещают целые complex16 значения без округления.
Heap-таблицы не добавляются; alignment16B, другие адреса сохраняют C fallback.
Размеры8…8192 проверяются на плате по независимому index oracle, C и involution.
Новых heap-буферов на processing path нет, но используется фиксированный
stack scratch. Подробности и ограничения — в README стенда.
`GMF_BENCHMARK_4096_ONLY` ограничивает performance sweep размером4096.
Отдельный `GMF_R4_STAGE_PROFILE` использует CPU cycle counter, выводит время
в микросекундах и маркирует строки как диагностические; его времена не являются
performance-результатами образа без instrumentation.
Он отдельно измеряет общую permutation в R2/R4. Остальные stage fields для R2
не собраны (`detail=permutation_only`), их нули не означают нулевую стоимость.
Core timer включает перестановку и real split, но исключает staging input;
full timer измеряет production process от уже оконного native входа до Re/Im.
Native-only выход не содержит magnitude/power/PSD или Float32 адаптер GMF.
В расширенном стенде общий FFT-allocator предварительно инициализируется
минимальным достаточным размером отдельно для каждого маршрута. Это отличается
от обычной политики compiled maximum. Недостаток RAM маркируется явно.
Q15 precision и насыщение оцениваются отдельно от PASS инфраструктуры стенда.
Факт сборки для target не заменяет аппаратные замеры; результаты ESP32/S3
также не являются измерением на процессоре без FPU.

`GMF_SPECTRUM_ONLY=ON` в firmware example выгружает точный Q15-вход и все
комплексные bins N4096 для слабых тонов и детерминированного шумового входа.
Hex-слова сохраняют значения без десятичного округления. Это отдельный
диагностический образ без timing sweep. Графики ошибки строятся относительно
double FFT того же квантованного входа, а не идеального сигнала до квантования.
Для Parseval-эквивалентного SNR и RMS ошибки half-spectrum использует вес1
на DC/Nyquist и2 на остальных bins. Ложные линии, bias и насыщение не следует
описывать только как белый шум. Графики dBc задают reference сильным тоном;
дБFS — единичным full-scale уровнем; PSD требует отдельной нормировки.

В сравнительных отчётах время указывается в мс в каждом числовом столбце,
память — отдельно в КиБ (1024B). Бюджет RAM разделяет workspace, caller buffers
и общие SDK-таблицы; таблицы учитываются один раз на процесс. Native GMF
возвращает int16; перевод в Float32 выполняется только вне таймера для сверки.
