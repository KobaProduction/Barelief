# API исполнения

[Переносимое ядро](../architecture/portable-core.md) · [Desktop runtime](../architecture/desktop-runtime.md)

Публичные контракты находятся в [runtime.h](../../libs/dataflow_runtime/include/dataflow_runtime/runtime.h),
[graph_lifecycle.h](../../application/include/application/graph_lifecycle.h) и
[processing_control.h](../../application/include/application/processing_control.h).
Этот справочник описывает назначение границ; точные сигнатуры и defaults задают заголовки.

## Модель и подготовка

`FrameBuffer` формирует Float32-векторы заданного `size` с явным `hop_samples`.
До заполнения первого кадра он не публикует данные; затем синхронно выдаёт все
полные кадры, даже если один входной пакет завершает несколько окон. Хранение
кольцевое и выделяется при подготовке. Fs, FFT, оконной функции и bypass у этого
этапа нет. Разрыв/недоступность очищают накопленную часть; первый новый полный
кадр сохраняет маркер разрыва. При наличии sample interval выход описывает
точный диапазон сохранённых отсчётов. Обычный `Window` продолжает хранить
последние N значений и не получает расписание кадров.

`FrameStride` пропускает дальше первый numeric-кадр и затем каждый `every_n`-й,
без изменения dtype/shape/clock и вычисления Fs. Пропущенные кадры не создают
выходных событий. Разрыв сбрасывает фазу шага и передаётся с первым новым кадром.
Шаг изменяется через обычный параметр/Apply; обработка не выделяет память.
Это отбор целых кадров, а не ресэмплинг их содержимого.
Явный `materialize=true` копирует только выбранный кадр в подготовленный
выходной буфер, в логическом хронологическом порядке, без кольцевого borrow.
Значения (включая типизированные нули маски) и координаты сохраняются;
пропущенные кадры не копируются. По умолчанию `materialize=false`.
Такой снимок после шага позволяет передать History в ограниченный владеющий
batch-вход; асинхронное удержание исходного кольцевого представления запрещено.

`FeatureAggregate` принимает mono Float32 vector либо matrix и переиспользует
общую редукцию признаков: method1=mean,2=median(default),3=sum. Вектор превращается
в scalar; каждая строка матрицы — в одно значение выходного вектора.
FFT, Mel, разности и хранение истории в этот блок не входят. Результат имеет
индексную ось строк; операция не назначает значениям новую частоту или секунды.
Clock и временная метка сохраняются. Скаляр — одна точка признака, поэтому
PCM-интервал sample_begin/sample_count снимается; обычный Window накапливает
такие точки без трактовки их как исходных аудиоотсчётов.

`NumericProcessingGraph` владеет узлами, портами, параметрами, связями данных и
отдельными конфигурационными зависимостями. `resolve_processing_node` проверяет
операцию, `admit_processing_graph` — topology, контракты, actual capability query
и ресурсные ограничения. Наличие dtype в общем списке не разрешает любой kernel.

`lower_routing_points` выполняется после явного lowering dtype-конвертеров.
`Reroute` удаляется из prepared topology, а его потребители подключаются к
исходному выходу напрямую. Исходный snapshot сохраняется для редактора;
`port_contract`, numeric callbacks и History queries поддерживают исходный
адрес точки через alias. Payload/scratch buffers и DSP State для неё не
создаются; дополнительная память нужна лишь описанию topology и aliases.

`NumericRuntimeProfile` задаёт admission, memory и kernel limits, поддержку
History, bounded delivery и необязательные платформенные часы измерения.
`PreparedGraph::numeric_capabilities(profile)` возвращает query фактически
доступных сочетаний; profile/context должен жить дольше использующих его query.

`PreparedExecution` объединяет immutable `PreparedPlan` и mutable
`RuntimeContext`. `GraphExecutor::prepare_numeric` выделяет память до обработки.
Для desktop `snapshot_preparation_base`, `prepare_numeric_detached` и
`register_prepared` разделяют холодную подготовку и сериализованную регистрацию.
`apply` проверяет владельца bundle/base; лишь успех потребляет bundle и
активирует план. Совместимое состояние переносится из актуального working context.

## Lifecycle и CONTROL

`GraphLifecycle` вызывает `NumericGraphPreparationPort` и `GraphRuntimePort` для
Prepare, Apply и connect/disconnect. Composition сериализует контроль, обработку
и query. Ошибка подготовки/замены сохраняет рабочий план; owner teardown использует
`shutdown_transactional`. Пользовательского Start/Stop нет.

`ProcessingControlService` добавляет session identity, CAS revisions,
единственного pending owner/token/TTL, replay и registered parameter updates.
Replies содержат borrowed graph/capabilities и требуют owning-проекции до
асинхронной отправки. `working_numeric_snapshot()` даёт общий immutable DTO-owner
для replay без удержания kernels. `ExplicitPersist` сохраняет applied graph
revision через отдельно подключаемый `ProcessingPersistencePort`.

Интервал анализа `execution_interval` по умолчанию `{1,120}` секунд, сокращённая
положительная дробь в диапазоне 1 мс–60 с. Он определяет шаг в signal timeline,
а не период GUI timer. Fs и время поступления источника сохраняют отдельный смысл.

## Обработка и владение

| Вход | API / правило |
| --- | --- |
| Обычный numeric/structured frame | `process_numeric_ports`: borrowed input потребляется синхронно |
| External History | `process_numeric_owned_ports`: owning frame, обязательный row ordinal и owner, удерживающий storage/pools |
| Локальная синхронизация и внутреннее время генераторов | `process_clock` |
| Недоступный источник | `advance_unavailable_source`: известный contract/clock позволяет typed silence |

`NumericRuntimeCallbacks` отдельно публикует результаты выходных портов и входов потребителей с
точной identity, contract, FrameStamp, status и DeliveryStamp. Все callback views
заимствованы только до возврата. Асинхронные очереди приобретают ограниченного
владельца; borrowed frame нельзя просто сохранить в контейнере.

Prepared processing не читает JSON, не выполняет transport I/O и не расширяет
контейнеры. Совместимый обход обычной операции передаёт вход, несовместимый
публикует типизированные нули; маршрутизаторы сохраняют свои явные правила.
Смена связи не даёт разрешения сбросить всю совместимую историю.

## History и диагностика

`Spectrogram` принимает scalar либо vector с постоянной шириной. Для scalar
выход имеет форму `[Time][Band=1]`; для vector сохраняется его ось признаков.
`NumberAccumulator` сохраняет scalar как vector `[Time]`. Обе операции имеют
явную ёмкость2…4096; допустимость конкретной формы, памяти и размера кадра
дополнительно ограничивает профиль исполнения. Увеличение доступной настройки
не меняет ограничения транспортов или профиля ESP32.

`NumericHistoryRowView` передаёт выбранную компактную строку, событие,
`filled_count`, capacity и `accepted_row_ordinal`. Полный `history(...)` —
сериализованный borrowed snapshot ring; удержание полного снимка выполняет адаптер.
Полная capacity существует с нулевым старым хвостом, occupancy и ordinal не
выводятся из размеров матрицы. Resize сохраняет новейшие реальные кадры и не
создаёт новые timestamps/ordinal.

`signal_contracts::history_row` возвращает заимствованную строку без копирования
payload: для матрицы — вектор, для векторной истории скаляров — скаляр.
Логический индекс учитывает кольцевой буфер и маску тишины; контракт строки
сохраняет dtype, quantity, единицу и каналы исходного элемента.
`NumberAccumulator` и подключённый к нему sink публикуют компактные события
обновления. Рабочие plane layouts готовятся до исполнения. Полный массив истории
по-прежнему получается через явный cold snapshot, а не копируется на каждом кадре.

`RhythmAnalyzer.sample_rate` поддерживает явный параметрический вход
`target_sample_rate_input`. В стартовой схеме он соединён с Fs-выходом
ресэмплера332. При смене Fs параметр меняется через эту связь; схема без
подключения использует явно сохранённое значение и должна согласовать его
с входным контрактом. Метод анализа и частота публикации признаков не меняются.

`NodeStats` содержит calls, produced, errors, self total/max nanoseconds,
16 histogram bins и deadline misses. `MixerInputStats` — depth/capacity,
dropped/underrun samples. Часы измерения предоставляет platform; export и
форматирование выполняются вне processing path.

Desktop использует [EnginePort](../../presentation/ports/include/pipeline/engine_port.h):
Snapshot, ApplyGraph, Subscribe; коррелированные EngineReply и EngineSnapshot;
owning numeric frame, History row и cold snapshot callbacks.
Скрытие UI не должно становиться командой shutdown runtime.

## Матричные операции

Операции имеют отдельные узлы и один матричный вход/выход:

- `MatrixTranspose` меняет местами элементы, размеры и координаты двух осей.
  History `[Time][Band]` превращается в `[Band][Time]`. Ring читается в
  логическом порядке; выход — обычная матрица без ring.
- `MatrixCenter` центрирует строки Float32 независимо по всем фактическим
  столбцам. `method=0` (default) вычитает среднее; `method=1` вычитает
  `(min+max)/2`; `method=2` вычитает общий ручной `offset` (default 0).
  Геометрия, координаты и часы сохраняются, выход имеет normalization None.
  По умолчанию узел включён. Пустые строки не требуют ожидания, постоянная
  строка в автоматических режимах превращается в нули. Generic bypass
  передаёт вход только при совпадающем физическом контракте; при FloatUnit
  на входе и None на выходе применяются обычные правила typed silence.
- Окно строк применяется через `WindowFunction → ArrayMultiply`: вектор
  коэффициентов повторяется по всем строкам, без специального матричного окна.
- `Fourier`/`RealFourier` преобразуют каждую фактическую строку Float32 длины N
  одним подготовленным планом. Часы и координаты строк сохраняются;
  преобразованная ось содержит индексы бинов. Fs, окно, дополнение нулями,
  амплитуда и фаза не входят в FFT. Полные/компактные выходы описаны ниже.
- `MatrixRow` выдаёт выбранную строку `row` как vector с координатами столбцов.
- Накопители `Spectrogram`/`NumberAccumulator` имеют `filled_only` (default false).
  При true обычная публикация и History snapshot содержат только заполненные
  строки/значения в хронологическом порядке, без копирования всего буфера.
  Ёмкость и отдельный filled count сохраняются; до первого кадра снимок пуст.
  Режим является явной настройкой и сохраняется в JSON вместе с capacity.
- `Mel` — линейная проекция спектра через общий `dsp_kernels::MelFilterBank`.
  Принимает Float32 vector `[bin]` или matrix `[время][bin]`, включая кольцевую
  историю и её фактическое число строк. Число `bands` ограничивается профилем
  исполнения, фиксированного предела50 нет. Входные частоты задаются собственными
  `sample_rate`, `bin_hz`, `first_bin` либо `frequencies_hz`; координаты кадра
  проверяются против этой сетки и не подменяют настройки вычисления.
  `scale=htk/slaney`, `fmin_hz`, `fmax_hz` (0: Nyquist), `norm=none/slaney/l0/lp/maximum/minimum`
  и `norm_p` задают банк фильтров. Default HTK/none сохраняет прежний смысл
  треугольной редукции. Амплитуда, мощность и их единицы не смешиваются:
  FFT, возведение в степень, логарифм и нормировка0…1 выполняются отдельно.
- `PowerToDb` переводит явно переданную линейную мощность Float32 в dB.
  `reference_mode=value/maximum`, `reference`, `amin`, `top_db_enabled`, `top_db`
  и `reduction_axes=all/rows/columns` определяют опору и ограничение диапазона
  для текущего переданного массива. Состояние предыдущих вызовов и будущие
  кадры не используются. Пустой массив при включённом поиске максимума
  даёт unavailable. Mel и dB доступны независимо от включения музыкальных методов.
- `RhythmFeatures` проецирует RFFT4096 либо2048 peak-amplitude bins в64/96
  линейных Float32 полос0…1 без UInt8-квантования. `input_representation`
  явно выбирает `complex` или `peak_amplitude`; несовпадающая геометрия
  отвергается. Сохраняются DC/Nyquist partition и масштаб диагностического R4.
  `RhythmAnalyzer` принимает Float32 историю этих полос либо другого
  совместимого линейного ряда. Byte encoders остаются отдельным DSP API.
- `OnsetStrength` — отдельный перенос `librosa 0.11.0 onset_strength(S=…,
  ref=None)`: Float32 история `[время][полоса/bin]` → Float32 огибающая по времени.
  Вход S задаётся явно (обычно log-power Mel, unit Decibels; также Values), без
  скрытых FFT/Mel/log/UInt8-преобразований. Параметры `lag`, `max_size`, `n_fft`,
  `hop_length`, `center`, `detrend`, `aggregate=mean/median/sum/none` задаются явно.
  `none` сохраняет матрицу по времени и признакам с координатами feature axis;
  остальные режимы выдают вектор по времени.
  Для потокового Float32-вектора поддержаны center=false, detrend=false,
  aggregate=none: блок хранит lag предыдущих кадров и возвращает положительные
  разности текущих полос с max-фильтром по частоте. Межполосная агрегация
  вынесена в FeatureAggregate; истории PCM, FFT или Mel внутри нет.
  Max-фильтр использует reflect по частотной оси; center добавляет слева
  `lag + n_fft // (2*hop_length)` нулей и обрезает результат до длины S.
  Каждая переданная история оценивается самостоятельно, с нулевым начальным
  состоянием detrend. Без center длина может вырасти до lag; при возможном
  дополнении explicit-времена не выдумываются, выход объявляет индексную ось.
  Огибающая не нормирована к0…1, после detrend возможны отрицательные значения.
  Агрегация использует компенсированную Float32-сумму; detrend также Float32.
  Поиск пиков, вероятности долей, BPM и сетка в этот блок не входят.
- `TempoEvidence` принимает отдельные Fourier short/long, linear ACF short/long
  и UInt64 заполненность двух историй. Fr, размеры FFT и диапазон BPM задаются
  явно. Fourier-входы содержат неотрицательный модуль, полученный отдельным
  `ComplexPolar`/`AmplitudePhase`, с DC и опциональным Nyquist: N/2 либо N/2+1
  значений. Raw Re/Im не являются модулем. Вычисления и выход0 — Float32: матрица8×7 BPM, score, Fourier short/long,
  ACF short/long, маска исходных кривых; выходы1/2/3 — UInt32 count, Float32 maturity и UInt8
  ambiguity. Неиспользованные строки нулевые. Подготовленные буферы объединяют
  только совпадающие интервалы, включая epoch/generation; старые незавершённые
  наборы отбрасываются. FFT и истории внутри блока отсутствуют. Маска кривых
  не означает независимые источники, score не является вероятностью доли.
- `MatrixAutocorrelation` рассчитывает линейную автокорреляцию каждой строки
  Float32, с нормировкой на энергию двух перекрывающихся отрезков. Выход
  содержит задержки0…`min(max_lag, columns-1)`, signed коэффициенты−1…1.
  Нулевая энергия даёт0; DC-смещение удаляется отдельным `MatrixCenter`.
  Отрицательные коэффициенты сохраняются, концы строки не замыкаются.
  `max_lag` задаётся явно (0…4095, default120); `frame_rate_fps` (1…1000000,
  default60) задаёт шаг задержки в секундах1/Fr независимо от audio Fs и
  метаданных соседних узлов. Caller отвечает за соответствие реальному потоку.
  Память строки и результата подготовлена заранее, processing не выделяет память.
  Вычисления прямые O(rows×columns×lags); снижение cadence и MCU-цена ещё
  требуют измерений. Коэффициент корреляции не является вероятностью доли.

Цепочка `History → MatrixTranspose → MatrixCenter → ArrayMultiply → RealFourier`
использует тот же вектор окна, что и последующая коррекция `AmplitudePhase`.
Для FFT512 строка на входе должна содержать512 значений. На выходе —
Re[row][256], Im[row][255] и DC[row]; временные координаты истории не выбирают Fs.
Нули и неравномерные метки не делают FFT недоступным; нечисловые данные
и неверная длина отвергаются. Частотная разметка подключается явно после FFT.

Raw Re/Im подключаются к `AmplitudePhase`;
выбранная численная плоскость разветвляется на обычные матричный и строчный
просмотры. Представления не выполняют DSP.
Выбор строки не сбрасывает History. Буферы транспонирования, коэффициенты
окна, результаты FFT и workspace выделяются при подготовке схемы.
При совместимом bypass кольцевой вход `MatrixCenter`
материализуется в обычную матрицу: сохраняются логические
значения, координаты и маски тишины, без присвоения выходу идентичности History.

`WindowFunction` использует общий по редакциям
неизменяемый банк: при подготовке геометрии рассчитываются Hann, Hamming,
Blackman, Rectangular, Bartlett, Blackman–Harris и Flat top. Смена функции при той же длине выбирает
готовый набор коэффициентов. Для переменной фактической длины подготовлены
повороты тригонометрической рекурсии: processing не вызывает sin/cos и не
выделяет память. Размер банка растёт линейно с максимальной длиной; он входит
в admission бюджета памяти. Mutable cache короткого окна принадлежит контексту
и не переносится между функциями без соответствующих коэффициентов.

Редактор распространяет изменения по ветви при изменении контрактов портов.
Смена функции окна, bypass или выбранной строки с прежними портами обновляет
только параметры узла: связи сохраняются, повторная подготовка Qt-моделей всей
ветви не выполняется. Исполнитель по-прежнему принимает полную схему атомарно.
Дискретный выбор оконной функции, её bypass и строки запрашивает Apply в
ближайшем проходе event loop, без задержки объединения текстового ввода.

## Исследовательские музыкальные операции

Новые числовые Fourier-узлы отделяют вычисление от спектрального представления:

| Stable kind | Входы | Выходы |
| --- | --- | --- |
| `Fourier` | Отдельные Float32 Re[N] и Im[N] | Отдельные Re[N] и Im[N], k=0…N−1 |
| `RealFourier` | Float32[N] | Re[N/2] (k=1…N/2), Im[N/2−1] (k=1…N/2−1), scalar DC |
| `AmplitudePhase` | Отдельные Re/Im; опциональный массив окна | Амплитуда формы Re и фаза в радианах формы Im |

Выходные ID: 0=Re, 1=Im; только у Real FFT 2=DC. Входные ID:
0=Re, 1=Im у комплексного блока. `fft_size` и `radix` — настройки FFT;
Fs не является его параметром/портом. Ось FFT содержит индексы бинов,
а время доставки/provenance сохраняются. Матрица `[строка][N]` преобразуется
по последней оси; один план используется для всех строк, DC становится vector.
Длина должна равняться N, скрытого дополнения/обрезания нет. Комплексный
radix2 принимает 2^m (N≥4), radix4 — 4^m; real-план (N≥8) поддерживает
radix2 и чистый/смешанный radix4. Верхний предел задаёт профиль исполнения.
У `AmplitudePhase` ID0=амплитуда, 1=фаза; `normalize=false` даёт сырые величины.
Этот блок принимает index/regular/explicit координаты. Explicit payload
обоих входов должен совпадать; runtime хранит только bounded owning copies.
`magnitude_norm=hypot/squared_norm/scaled_ratio_fma`, `zero_phase=zero/atan2`, `real_endpoints`,
`fft_size`, `first_bin`, `positive_half` задают численную политику явно.
Signed-zero Atan2 сохраняется, кроме явно выбранной real-axis политики.

Два подключённых входа должны иметь совпадающие временные интервалы,
producer epoch, generation и graph revision. Владеющие буферы подготавливаются
заранее. Пока второй вход не поступил, новая пара не публикуется; сохранение
borrowed view между вызовами отсутствует. Неподключённый вход — типизированный
ноль. Disabled-блок выдаёт типизированные нули, не исходный временной сигнал.
DC — raw коэффициент; знаковое среднее до окна вычисляется отдельной редукцией.
Подробности численных планов — в [FFT API](fft.md).

`Fourier.backend_id` — явная опциональная строка выбора численного backend.
Пустое значение сохраняет встроенный FFT. Непустое требует точного ID фабрики
из `NumericRuntimeProfile::fourier_backend`; профиль удерживает её через
shared_ptr, подготовленный backend независимо владеет планом и scratch.
Missing/mismatched provider или неподдерживаемый query отвергает подготовку
до публикации новой схемы, без fallback. Query учитывает staging/cold peak,
shared memory и hot stack; prepare сохраняет actual<=admitted guard.
Обработка использует заранее подготовленные буферы без hot allocation.
Обычные профили и RealFourier этот opt-in не выбирают автоматически.
Пример явной source-window/Float64 ODF границы —
[BTrack reference](../../examples/rhythm_operations/btrack/README.md).

`RealFourier.backend_id` выбирает RealForward того же явно подключённого
провайдера; пустое значение сохраняет PreparedRfft. Булева настройка
`include_endpoints` по умолчанию false: прежние размеры и выход DC2 неизменны.
При true выходы0/1 содержат по N/2+1 значений с bin origin0/step1, включая
DC и Nyquist в обеих плоскостях; отдельный выход2 сохраняет прежний контракт.
Actual строки матрицы и их координаты сохраняются. Новая геометрия доступна
также builtin-плану; непредставимые/неподдерживаемые запросы отклоняются до Apply.

Все операции выполняются общим executor. `NumericRuntimeProfile::music_enabled`
требуется только для `MusicalSpectrogram`, `NoteSpectrum` и `NoteSalience`;
общие численные операции и FFT от этого флага не зависят.
`resampler_backend` — внедряемый порт; desktop подключает SpeexDSP.
Профили и JSON декодируются внешними адаптерами, runtime получает typed arrays
и явные настройки, без JSON loader и поиска frontend по upstream-схеме.

`domain::music_output_contract` выводит выходной контракт из параметров и
реального входа. RFFT публикует Float32 `[N/2+1][2]`, `Axis::Bin/Component`,
один mono-plane, Re=0/Im=1. Вычислительные проекции имеют явные
quantity/unit для raw, phase, peak amplitude, coherent-corrected Power и PSD.
Шкала dB задаётся только представлением. Признаки требуют подходящей
линейной величины; одинаковый размер phase и Power не разрешает вычисление.
Broadband-координаты — explicit Hz-центры, нотные — regular MIDI-номера.
Quantize сохраняет координаты и clocks, меняя только dtype/шкалу кодов;
формула и оконные нормировки описаны в
[руководстве музыкального спектра](../guides/music-spectrum.md).

`PcmResampler` сохраняет kind и поддерживает `mode=bypass/existing_fir/compact_fir/speex/iir/linear`,
`output_rate` и `quality`. Bypass сохраняет исходную Fs; настроенная целевая
Fs остаётся параметром для следующего filtered-режима. `PcmPacketQueue`
принимает владеющие ограниченные PCM-пакеты со sample interval, обнаруживает
пропуски/повторение и возвращает дозированные части. Это отдельная
ответственность от ресэмплинга и накопителя `Window`.

`Window` принимает скаляр или вектор и сохраняет последние N значений.
Вход длиннее N заменяет содержимое своим хвостом, равный N заменяет его целиком,
короткий сдвигает историю и дописывается справа. До заполнения слева находятся
числовые нули. Каждый вход порождает один результат; тип и точность значений
сохраняются. Единственный параметр — положительный `size` (также явный вход N).
У блока нет Fs, hop, режима warm-up или bypass; размер ограничивает профиль
памяти, а не FFT. Временные метки входа сохраняются как сведения доставки.

`Fs` и `UInt32Constant` публикуют обычные UInt32 scalar. `SampleRate` извлекает
известную Fs входного контракта; `ArrayLength` выдаёт фактический размер входного
кадра по выбранной оси. Эти значения не являются сигналами синхронизации.
`Window.size` задаётся локально; default-карточка не содержит N command-входа.
`hop_samples=0` сохраняет рациональный шаг от частоты схемы; положительный
`hop_samples` задаёт постоянный шаг в отсчётах, независимо от GUI/analysis cadence.
`pad_start=true` сохраняет прежнее начальное дополнение нулями; при false
первый кадр ждёт полные N отсчётов и затем сдвигается на заданный hop.
После discontinuity полное окно накапливается заново. Совместимая история
фиксированного окна сохраняется при изменении частоты исполнения схемы.
`ArrayLength` от выходного окна передаёт измеренный размер следующим операциям.
Целевая Fs ресэмплера задаётся локальной настройкой `output_rate`; внешнего
входа управления целевой частотой нет. Resampler публикует фактическую выходную
Fs справа как UInt32 scalar (stable port 65534).
Подключённое значение N вычисляется
при подготовке из константы либо однозначных метаданных, включая прозрачную
разводку. Изменение значения требует новой подготовки затронутых контрактов;
буферы не изменяют размер во время обработки. Динамический размер переменного
кадра не допускается как параметр подготовки. Сохраняемая схема содержит эти
рёбра и порты; исполняемая схема исключает их из DSP-расписания.

Источники `SignalGenerator`, `AudioSource`, `TestSignal`, `NetworkInput` имеют
дополнительный обычный UInt32 scalar выход Fs (stable port 65534). Его значение
и доступность следуют кадрам того же источника. Компиляция схемы представляет
этот выход отдельной операцией чтения метаданных, сохраняя исходный endpoint
наблюдения. Fs не увеличивает число физических аудиоканалов.
`AudioSource.output_count` ограничивает количество опубликованных ведущих
каналов устройства (0 — все native-каналы). Основной пример оставляет все native-каналы и соединяет только один из них.
Захват остаётся native; адаптер выбирает соответствующие плоскости без смешивания. Вход Fs_in (65531)
у `PcmResampler` и `Window` проверяет соответствие частоты реальному входному
контракту; он не переименовывает физическую частоту данных.

`InputSelector` допускает разные входные Fs и сохраняет частоту выбранной группы.
Каждая группа содержит независимые типизированные значения: например,
mono-аудио и явно подключённый Fs scalar от источника. Выходы выбираются
по позиции внутри группы; переключатель не извлекает и не создаёт Fs сам.
Для числового параметра Fs подготовка следует реальному проводу выбранной группы.
Обе линии одной аудиогруппы имеют общий источник; разные независимые источники не становятся
синхронными из-за одинаковой Fs. После переключателя нужен явный Resampler,
если следующая ветвь должна иметь постоянную Fs.

`SpectrumPeak` принимает mono Float32 vector в native encoding с normalization
None. Он выбирает первый строго положительный максимум; при равенстве остаётся
первый индекс. Собственные параметры `bin_hz` (default 1, 1e-15…UInt32 max) и
`first_bin` (default 0, 0…UInt32 max) задают частоту явно:
`Hz = (first_bin + index) * bin_hz`. Их preparation-входы имеют stable IDs
65526 (Float64 `bin_hz`) и 65524 (UInt32 `first_bin`). Factory задаёт начальные
`bin_hz=Fs/N` и `first_bin=1` из собственной явной конфигурации; сохранённые
настройки узла определяют результат, частотная ось входного metadata не подставляется.
Выход 0 — Float32 scalar Hz, выход 1 — Float32 scalar максимума с unit/quantity
входа. Clock сохраняется. Если положительных значений нет или узел выключен,
доступный кадр даёт 0/0; недоступный вход остаётся недоступным. Неконечные входы
и непредставимый результат делают оба выхода недоступными.

`WLEDEncode` преобразует подключённые значения в пакет Audio Sync. Дополнительные
поля пакета `peak_hz` и `magnitude` принимаются через явные scalar-входы 1 и 2;
вход 0 принимает Mel-массив. Собственные зарегистрированные числовые настройки
`peak_hz`/`magnitude`, по умолчанию нулевые, используются только при отсутствии
соответствующего подключения. Допускаются конечные неотрицательные значения
в диапазоне Float32. `gain` остаётся отдельной настройкой кодирования.
Подключённые значения сопоставляются с Mel по идентичности кадра и часов;
порядок доставки ветвей не определяет результат. Ожидающий Mel хранится
в ограниченном владеющем буфере. Недоступный подключённый вход не заменяется
старым значением или локальным default. Узел не ищет спектральный пик и не
наследует его через состояние родителей; для динамических полей используется
явный вычислительный путь, например отдельный `SpectrumPeak`.

Внутренний fixture-адаптер `SpectrumAmplitude` принимает модуль ненулевых коэффициентов и N. Для
положительной половины нормировка равна `2/N`, кроме конечной точки чётного N,
для которой используется `1/N`. Для полного комплексного спектра используется
`1/N`. Параметр `coherent_gain` задаёт дополнительную явную оконную поправку;
по умолчанию она равна 1. Частота дискретизации здесь не используется.
`FrequencyStep` принимает обычный UInt32 Fs и подключённый UInt32 размер N,
выдаёт Float64 шаг Fs/N. Нулевой Fs делает результат недоступным.
`SampleRate` — отдельная видимая операция измерения собственного объявленного
входного контракта: её scalar-выход подключается обычным ребром. Неизвестная Fs
даёт недоступный результат. Операция не вставляется автоматически; потребители
не ищут Fs в чужих кадрах или upstream-топологии. Стартовые схемы используют
прямой Fs-выход источника.
`FFTView` имеет собственный Float64-вход шага частоты65526 и параметр
`first_bin`. Подключённый шаг задаёт координаты `(first_bin+i)*bin_hz` в Hz;
без провода график показывает индексы, даже если старые координаты остались
в данных. Параметры оси берутся из применённой схемы. Смена шага не меняет
значения массива и не выполняет повторный FFT. В стартовой схеме отдельные
провода соединяют FrequencyStep со всеми FFTView, first_bin=1 для выхода
Fourier без DC. Обычный полный массив можно показывать с first_bin=0.

Массив спектра передаётся напрямую. `FrequencyStep` выдаёт отдельный Float64
шаг частоты; он подключается к `FFTView`, `BroadbandRow` и `NoteSpectrum`
обычными числовыми проводами. Без шага график показывает индексы.

`AmplitudePhase` использует общий парный Re/Im механизм.
Оба подключения обязательны, плоскости должны иметь одинаковую геометрию
либо компактную real-геометрию с последним Nyquist только в Re;
требуются совпадающие интервалы/эпохи/поколения; неполная пара даёт недоступность,
а не нулевую мнимую или действительную часть.
На карточке выбирается линейная выходная величина: модуль FFT,
peak amplitude, спектр мощности или PSD; второй выход всегда содержит фазу в радианах.
Переключатель «Компенсация FFT и окна» (`normalize`, стабильный ключ)
общий для всех четырёх представлений, на фазу не влияет. Это компенсация
масштаба преобразования и окна, а не приведение максимума кадра к единице.
Численные формулы реализует `dsp_kernels::PreparedSpectrumScaling`.
Графовый AmplitudePhase передаёт ему отдельные Re/Im и признак парного бина;
`PreparedSpectrumProjection` адаптирует к нему interleaved RFFT пакетного анализа.
Оба используют `SpectrumProjectionOptions` с видом спектра и явным флагом
компенсации. Список амплитудных представлений предоставляет общий реестр ядра.
Перевод значений в dB задаётся исключительно настройками графика.
Fs (65532, UInt32) задаётся явно только для PSD/частотных координат. Нулевой Fs
допустим для остальных представлений: выход сохраняет числовые координаты.
Окно подключается одним входом65523 (`window_coefficients`, Float32 vector).
Массив оценивается на холодной подготовке через `PreparationValueProvider`
или capability конечного генератора; потоковый массив без такой capability
отклоняется. Исполняемый узел владеет коэффициентами и кэширует C/E;
сохранённая схема содержит связь и параметры производителя без дубликатов массива.
Суммы на каждом аудиокадре не рассчитываются. Отключение связи очищает поправку,
применяется C=E=N. Старых scalar-входов C/E у AmplitudePhase нет.
`fft_size` задаёт N явно, `first_bin` — первый коэффициент, `positive_half` —
наличие только неотрицательной половины. Выбранная подполоса проверяется
против N; DC и even Nyquist имеют единичный sidedness multiplier.
N не восстанавливается из размера или метаданных чужого кадра; C/E вычисляются
из явно подключённых коэффициентов. Короткое окно допустимо при явном padding до N.
Частотные координаты обеих выходных плоскостей
задаются явно как k*Fs/N; raw Fourier по-прежнему Fs не использует.

`WindowFunction` принимает UInt32 scalar N на входе 0 и генерирует Float32[N]
при `precision=0` (по умолчанию), Float64[N] при явном `precision=1`.
Другие значения precision отклоняются. Double Hann вычисляется общей
центрированной cosine-series формулой; коэффициенты w[n] и их буфер готовятся
холодно и публикуются на выходе 0. Сигнал на вход N не передаётся. Размер может
поступать из `ArrayLength` готового окна; `size` служит подготовленным размером.
Применение окна — отдельный `ArrayMultiply`: массив отсчётов × w[n].
`periodic=false` задаёт симметричное окно; `periodic=true` — периодическое для
DFT. Для N>1 периодическое окно эквивалентно симметричному длины N+1 без
последнего коэффициента. При N=1 коэффициент равен1 в обоих режимах.
Банк повторно используется только при совпадении размера и режима;
поправки амплитуды используют фактические коэффициенты выбранного режима.
Банк коэффициентов готовится до обработки; повторное событие того же N публикует
готовое хранилище с новым stamp. Несоответствующий подготовленному размер N
отвергается, изменение размера требует подготовки затронутой ветви.
У генератора один выход, массив выбранной точности; дополнительные C/E выходы удалены.
Генерация и коррекция используют общую platform-free window_math.
При отключённой связи окна C=E=N. При включённом нормировании положительные
внутренние бины имеют peak amplitude = 2*abs(X)/C, power = 2*abs(X)²/C²,
PSD = 2*abs(X)²/(Fs*E), нормированный модуль = abs(X)/C.
У непарного Nyquist множитель 2 заменяется на 1;
для полного комплексного спектра также используется 1.
При выключенном нормировании модуль/peak выдают abs(X), power/PSD — abs(X)²;
quantity/unit и подпись выхода отражают raw magnitude либо raw squared magnitude,
а не физическую PSD. Шкала dB настраивается только графиком:
20*log10 для амплитуды, 10*log10 для мощности/PSD, с отдельными
reference и floor представления. Тональная power-нормировка
и PSD-нормировка окна различаются намеренно.

`ArrayMultiply` применяет массив оконных коэффициентов как один из равноправных
множителей. Контракт, координаты и время результата задаёт его явный
`frame_input`; Fs/N, частотный профиль и FFT-происхождение не выводятся из
других входов. Частоты автоматически не выравниваются. Полный контракт
операции с несколькими входами описан в разделе «Поэлементное произведение
массивов» ниже. Она доступна без music capability.
`ArrayFill` создаёт массив коэффициентов заданного значения по UInt32 scalar
размеру на входе 0; `size` задаёт размер
подготовки, `value` — значение (по умолчанию 1). Банк заполняется при подготовке.
В основном примере числовой размер извлекается из Re FFT; значения амплитуд
к генератору коэффициентов не подключены. Загрузка рассчитанной кривой коррекции
относится к отдельному источнику данных, а не к операции умножения.

`FrequencyNormalizer` остаётся отдельной операцией существующих профильных
примеров и не используется в основном startup. `NoteSalience` получает
численную трактовку входа из собственных настроек `input_representation`,
`first_bin`, `include_nyquist`, `bin_hz`, `coherent_gain` и
`power_bandwidth_hz`, а не выбирает
формулу по описательному `quantity` входного кадра. `bin_hz` задаёт координаты,
`coherent_gain` здесь задаёт сумму коэффициентов окна `C=sum(w)` для
калибровки raw DFT magnitude, а `power_bandwidth_hz` — эквивалентную шумовую полосу окна
`Fs * sum(w²) / sum(w)²` для перевода PSD в power. Эти величины совпадают лишь
для некоторых окон. В подготовленном workspace внутренний peak-amplitude bin
даёт `A²/2`, непарные DC и Nyquist — `A²`.
Для парного бина мощность равна `2*(M/C)²`, для DC и Nyquist — `(M/C)²`.
PSD умножается на `power_bandwidth_hz`. В музыкальном примере `C` вычисляется
общим `window_sum` для окна Hann и размера FFT, а не извлекается из метаданных кадра.
Если вход пропускает
DC, нулевой элемент добавляется только во внутренний workspace, не в FFT-выход
или показанный спектр.
DC Re/Im — raw коэффициенты нулевой частоты; для вещественного входа DC Im=0,
DC Re/N равно среднему входного окна. Основная спектрограмма их не подключает.
DC сохраняют стабильные ID 2/3 и по умолчанию скрыты на карточке. Действие
«Показать DC-выходы» меняет зарегистрированное presentation-поле
`show_dc_outputs`; соединённые DC остаются видимыми независимо от этого флага.

`Number` — обычный scalar источник с literal int64/uint64/float32/float64.
Fs/UInt32Constant сохраняются как специализированные ограниченные числовые
примитивы, но в основной схеме константы размера нет. Короткая подпись порта
показывает dtype и размер (`float32[4096]`, `uint32`); подробности контракта
остаются в инспекторе.


### Оконные функции

Генератор `WindowFunction` и матричная оконная операция поддерживают Hann,
Hamming, Blackman, Rectangular, Bartlett, четырёхчленное Blackman–Harris и
пятичленное Flat top. Окна симметричны по `N−1`; CG/PG вычисляются по тем же
коэффициентам, которые выдаёт генератор. У Flat top допустимы отрицательные
краевые коэффициенты. Численные определения соответствуют
[Bartlett](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.windows.bartlett.html),
[Blackman–Harris](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.windows.blackmanharris.html)
и [Flat top](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.windows.flattop.html).
Все банки коэффициентов и вращения для переменной длины подготавливаются заранее;
расчёт размера памяти учитывает весь набор окон.

### Составной музыкальный ряд

`MusicalSpectrogram` принимает Float32 vector линейного спектра с
согласованными quantity/unit и равномерными координатами Hz. dB на входе
отклоняется, а логарифмическая шкала задаётся только графиком.
Вход не превращается неявно в энергетический спектр. Четыре выхода:

| ID | Данные |
| --- | --- |
| 0 | Составной ряд `[НЧ][СЧ][ВЧ][ноты]`, Float32 vector с индексной осью |
| 1 | Взвешенное совпадение пиков с полной оценочной сеткой, scalar 0…100 |
| 2 | Совпадение пиков внутри выбранного нотного диапазона, scalar 0…100 |
| 3 | Нотные значения с отдельными explicit Hz-координатами |

Для каждой группы `low/mid/high` задаются `*_low_hz`, `*_high_hz`, `*_count`
и `*_reduction`: `pass_through`, `mean`, `rms`, `weighted_mean`, `maximum`.
Pass-through требует count=0 и сохраняет каждый попавший bin. Другие режимы
равномерно разделяют последовательные bins по `floor(j*K/Q)`; пустая группа
даёт 0. RMS — `sqrt(mean(Y²))`, не RMS исходного PCM. Взвешенное среднее
использует явный input-sized `NumericArray weights`; пустой массив задаёт равные
веса 1. CSV разбирает внешний адаптер до передачи типизированных значений.
Вес неотрицателен; непустая группа с нулевой суммой весов отвергается.
Диапазоны не перекрываются и полуоткрыты; только последний ВЧ-диапазон включает
крайний доступный bin, если его верхняя граница совпадает с этой частотой.

Defaults: НЧ40…250 Hz без редукции, СЧ250…4000 Hz mean16, ВЧ4000…16000 Hz max8,
ноты MIDI21…108 включительно, A4=440 Hz. `first_midi/last_midi` изменяют нотный
выход; значения получаются линейной интерполяцией Y на частотах нот. Вне
доступного спектра нотное значение равно 0. Harmonic NoteSalience остаётся
самостоятельной исследовательской операцией и не подменяет эту интерполяцию.

Оценочная сетка `assessment_first_midi/assessment_last_midi` (default0…127)
независима от выбранных выходных нот. Полный процент использует все локальные
ненулевые пики выше `minimum_peak_level` в знаменателе. Выбранный процент
учитывает пики в пределах first…last с внешними полутоновыми границами.
Каждый пик учитывается один раз; flat top считается одним максимумом,
частота внутреннего пика уточняется параболой. Совпадение определяется
`cents_tolerance` (default20 cents). Для amplitude/magnitude веса равны Y²,
для power/PSD — Y. Без подходящих пиков соответствующий выход недоступен;
ноль процентов не подменяет отсутствие данных. Это описательные показатели
согласованности, не вероятность музыки или достоверность распознавания мелодии.

History хранит составной ряд как `[кадр][полоса]`. После ВЧ снова идут низкие
частоты нот, поэтому у всей составной оси нет единой монотонной шкалы Hz.
Интерфейс показывает индексы четырёх секций, отдельный нотный график — Hz.
Изменение границ, нотной сетки, агрегации или физической величины входного
спектра сбрасывает затронутую History даже при прежнем размере. Совместимая
независимая ветвь сохраняется. Изменение только оконных поправок CG/PG
не считается сменой смысла полос.

### Поэлементное произведение массивов

`ArrayMultiply` принимает от двух до128 фиксированных mono Float32/Float64 vectors
одинаковой длины (редактор ограничивает число портов своим admission limit).
Наличие Float64 множителя повышает результат до Float64 без промежуточного
Float32 округления. Чистые Float32 входы сохраняют прежнюю арифметику и память.
У отключённого узла остаётся контракт явного ведущего входа.
`RealFourier` принимает также Float64 vector/matrix, выполняет подготовленный
Double real FFT и публикует Float32 Re/Im/DC (округление на границе complex64).
Форма компактных портов не меняется. Float64 полный complex Fourier и
именованный Float32 backend с Float64 входом не поддерживаются; недостаточный
бюджет Double плана/буферов отклоняется до обработки.
Все входы — равноправные множители: quantity, unit, координаты и clock
не задают скрытых ролей первого и второго входов. Число множителей меняется
на карточке; существующие stable PortId и соединения сохраняются.

Для временной привязки результата параметр `frame_input` выбирает stable PortId
ведущего кадра; по умолчанию это PortId 0. Отрицательный Auto-режим не
поддерживается: quantity, unit, координаты и sample rate не выбирают ведущий
вход. В инспекторе доступен явный выбор существующего stable PortId.
Координаты, stamp и stream результата принадлежат этому входу. Остальные
множители удерживаются до следующего обновления; обновление коэффициентов
само по себе не выпускает повторно уже обработанный кадр. Ожидающий кадр и
координаты копируются в заранее выделенное владеющее хранилище.

Все подключённые множители должны быть доступны. Неподключённый множитель
имеет нулевые значения, а не скрытый единичный коэффициент. Недоступность
сбрасывает ожидающий кадр; старый кадр после восстановления не повторяется.
Для нейтральной коррекции используется явно подключённый `ArrayFill(value=1)`.
Bypass сразу пропускает ведущий кадр, не ожидая остальных множителей.
Активное произведение снимает FloatUnit normalization: численный результат
не обязан лежать в диапазоне исходного сигнала. Проверяются конечность и
представимость результата в Float32; обработка не выделяет память.

### Независимые спектральные ряды

`BroadbandRow` и `NoteSpectrum` принимают обычный mono Float32 vector и явный
Float64 шаг частоты `bin_hz` через порт65526. Индекс первого bin задаётся
`first_bin` (default1). Частота входного элемента i равна
`(first_bin+i)*bin_hz`; внутренний sample rate для этого расчёта не используется.
В основном примере оба входа соединены с выходом `FrequencyStep`.

`BroadbandRow` задаёт НЧ/СЧ/ВЧ диапазоны и их редукции независимо от нот.
Выход0 — один ряд с явными Hz-координатами центров ячеек. `NoteSpectrum`
независимо задаёт first/last MIDI, A4, оценочную сетку, допуск и минимальный пик.
Выход0 — интерполированные значения нот с явными Hz-координатами;
выходы1/2 — полное/выбранное совпадение пиков с сеткой, выход3 — обычный
UInt32 с первой MIDI-нотой. Этот выход подключается к `PianoView` через
вход65525 (`first_midi`): представление получает явное начало диапазона,
готовые значения из выхода0 и фактические Hz-координаты без повторного DSP.
Обычные линейные числовые массивы с Quantity Unspecified/Unit Values
допускаются для `BroadbandRow` и `NoteSpectrum` при собственном
`input_representation=linear`, без спектрального semantic/quantity маркера.
Нелинейные dB-представления отклоняются; выходная единица
соответствует линейной величине. Числа должны быть конечными и неотрицательными.
Формулы общие с `MusicalSpectrogram`, но независимые операции готовят и
выполняют только свои ячейки/ноты; широкополосный ряд не ищет нотные пики.

`MusicalSpectrogram`, `BroadbandRow` и `NoteSpectrum` объявляют собственные
`input_representation` и `peak_weight`; последний выбирает использование
входного значения либо его квадрата при взвешивании пиков. `bin_hz` и
`first_bin` задают вычислительную сетку явно. Quantity и координаты входного
кадра проверяются на соответствие заявленной политике, но не выбирают её.

`ArrayConcat` — отдельное соединение двух mono Float32 vectors произвольных
фиксированных длин. Выход `[левый][правый]` имеет индексную ось: совмещённые
частотные координаты не объявляются монотонными. При разных единицах результата
используется Values. Оба входа должны иметь общий clock; точные stamp/интервалы
должны совпадать. Операция владеет ожидающими массивами и не соединяет разные
поколения или моменты времени. Недоступность очищает обе ожидающие половины.

Основной пример имеет отдельные накопители и представления широкополосного
и нотного рядов, а также явный ArrayConcat и общий накопитель. Настройки каждой
ветви независимы. Изменение сетки или редукции сбрасывает историю этой ветви
и общий результат; совместимая история второй ветви сохраняется. Проверка
семантики общего накопителя обходит обе зависимости ArrayConcat.

Индикатор активности на карточке — телеметрия. Его изменение вызывает только
перерисовку элемента и не является изменением документа, Apply или автосохранением.


`ArrayReindex` принимает mono Float32 vector или matrix и явный массив
`indices` с конечными целыми индексами от0 до длины последней оси−1.
Выборка и перестановка выполняются по последней оси без изменения чисел.
Длина выбранной оси фиксирована; матричная ось строк и её координаты сохраняются.
Выбранная ось имеет индексы, clock/stamp сохраняются. Память индексов готовится
до обработки; неверные/дробные/отрицательные индексы отклоняются при подготовке.

`TemporalFrameSequence` преобразует полный mono Float32 vector в матрицу
`[кадр][отсчёт]` через общий PreparedTemporalWindow без оконного взвешивания.
Явные `window_length`, `hop`, `center=false`, `tail=0/1` задают Drop/CoverEnd.
CoverEnd дополняет последний кадр нулями до первого достижения конца входа.
Это batch-операция, без неявного накопления между вызовами; оси индексные.
Оконные коэффициенты и FFT применяются отдельными узлами. Большие session
матрицы требуют явно выбранного исследовательского профиля ресурсов.

Входные секундные координаты batch-последовательностей проверяются по явно
заданному `frame_rate`: шаг должен быть равномерным, начало снимка может быть
ненулевым или отрицательным. ExplicitFloat64LE проверяет конечность и строгое
возрастание; неверный шаг и неравномерная сетка отвергаются до вычисления.
Начало оси не задаёт скрытый параметр DSP. Выходные времена найденных событий
остаются относительными к началу входного снимка, как объявлено его рецептом.

`FrameBuffer` привязывает timestamp полного окна к первому сохранённому сэмплу,
пересчитывая смещение от начала текущего PCM-пакета через явные Fs и tick_seconds.
Произвольное начало часов сохраняется независимо от sample_begin. Поэтому шаг
окон и секундная сетка downstream History не зависят от размера входных пакетов.
Переполнение timestamp отклоняется; при неизвестном Fs исходный timestamp
остаётся непреобразованным, без выдуманной физической временной координаты.

`TempoAnalysis` и `CrfBeatSequence` имеют явный целочисленный параметр
`precision`: `0` — прежний PortableFloat32 (по умолчанию), `1` — DesktopReference.
Он не меняет входные и выходные Float32-контракты. В режиме1 offline mono Comb
без интерполяции сохраняет Double сглаживание/comb/гистограммы/поиск пиков до
окончательной публикации. Comb alpha сохраняет исходную Float32 точность.
CRF использует Double кандидатов при выборе целочисленных пробных интервалов,
но существующий decoder получает Float32 сглаженную активацию; factors для
режима1 не поддерживаются. Неподдерживаемый режим или сочетание отклоняется
атомарно, без подмены режима. `TempoHistogram` и `BeatTrackingSequence` не
получают этот параметр; размер данных и метаданные не выбирают точность.

Переносимые decoder/search/CRF различают `SequenceDecodeOutcome::Error`,
`NoPath` и `Path`. Нижние `PreparedIntervalSequenceDecoder` и
`PreparedIntervalSequenceSearch` возвращают `true` только для `Path`;
`PreparedCrfBeatSequence::process` возвращает `true` также для корректного
`NoPath`. В графе такой CRF публикует доступные пустые секунды и индексы,
а также текущую диагностику. Недостижимая проба имеет score `-Inf`;
отсутствие кандидата tempo представлено отдельной строкой `[NaN, 0]`,
а не допустимым BPM. Пробы не выполняются, если tempo отсутствует.

Неверный контракт, NaN/отрицательная активация, числовое переполнение и
противоречивая цепочка после выбранного конечного finite-состояния остаются
`Error` с причиной (`error_reason()`), `false` и без прежнего результата.
Нули, короткий корректный вход и отсутствие достижимого конечного состояния
дают `NoPath`; недостижимые внутренние состояния не отменяют другой найденный
finite-путь. Для короткого CRF cold query и prepare резервируют search scratch
не меньше максимального интервала модели. Фактический вход не дополняется
нулями, его длина и границы выходных событий сохраняются.
