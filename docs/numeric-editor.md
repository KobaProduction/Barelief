# Канонический числовой редактор Data Flow

Редактор задаёт маршрут обработки и контракты портов. DSP выполняет общий
`PreparedGraph`/`GraphExecutor`; графические модели узлов редактируют параметры
и показывают диагностику. Сохранение черновика не запускает обработку.

## Узлы и совместимость портов

Библиотека и контекстное меню используют один каталог: Sources (источники),
Processors (обработка), Outputs (потребители). Converter — явный процессор
преобразования числовых данных. Стабильные идентификаторы узлов и портов
сохраняются при смене языка, копировании и сохранении; вставленный узел получает
новый ID.

Числовой порт объявляет dtype, ранг, размеры, каналы, смысл данных, единицы,
представление и часы. Доступны Int8/UInt8, Int16/UInt16, Int32/UInt32,
Int64/UInt64, Float32/Float64 и ранги Scalar, Vector, Matrix. Совпадение формы
массива не делает PCM, спектр и Mel взаимозаменяемыми. Несовместимое соединение
отвергается; для преобразования используется Converter.

Splitter, Switch и Gate имеют зарегистрированные параметры маршрутизации.
Увеличение числа выходов сохраняет прежние совместимые связи. Уменьшение удаляет
связи исчезнувших выходов; Undo восстанавливает снимок узла и его связи.

## Компактный блок и инспектор

По умолчанию блок показывает название, порты и краткую диагностику. Полный
набор параметров находится в правом инспекторе выбранного узла. У каждого
редактируемого параметра есть переключатель «Показывать на блоке» / Show on block:
включение показывает тот же редактор внутри блока, выключение скрывает его,
сохраняя значение. Изменения из инспектора и блока синхронизируются, включая
точные числовые поля и Undo/Redo. При изменении числа портов обе формы обновляют
состав полей.

Выбор полей — данные представления `presentation.inline_parameters`, отдельно
от `ConfiguredProcessingNode`. Он сохраняется с проектом и preset, переносится
при QtNodes Copy/Paste и отменяется через Undo, не входит в processing graph,
Apply или remote protocol. Начальный список пуст: существующие файлы без этих
флагов открываются с компактными блоками.

Только при отсутствии локального файла конфигурации первый запуск получает
TestSignal preset с восемью изменяющимися тонами, без звука через динамики.
Начальная раскладка и центрирование выполняются один раз после готовности
видимого viewport. Открытие существующей конфигурации, повторный показ редактора
и обычное изменение размера не сбрасывают пользовательские позиции и камеру.

## Точные параметры, черновик и Apply

Типизированные числовые поля вводятся как текст с проверкой диапазона.
Int64/UInt64 не проходят через `double`: например, `9007199254740993` и
`18446744073709551615` сохраняются точно. Undo/Redo и QtNodes Copy/Paste
используют владеющие типизированные снимки.

Converter задаёт входной и выходной контракты, округление, переполнение, политику
потери точности, обработку NaN/Infinity и масштабирование. Целочисленные,
диадические и другие зарегистрированные режимы масштабирования выбираются явно;
коэффициенты, показатели степени и значения замены сохраняют свои типы.

Apply передаёт текущий черновик в канонический движок. Подтверждение Apply
относится к отправленному снимку; последующая правка не делает новый черновик
активным. Неверный импорт не заменяет текущую схему. Кнопка загрузки Applied
Data Flow возвращает активную схему в редактор. Явный Stop отделён от изменения
связей и параметров.

Preset хранит схему, точные параметры и представление редактора, включая
положение узлов. Загрузка preset меняет черновик; применение выполняется
отдельно. Доступны сохранение, загрузка и удаление пользовательских preset.
Проектное сохранение сохраняет неизвестные поля и точные числовые значения,
разделяет черновик и применённую схему. Текущие форматы: graph version 3,
processing version 2; визуальный снимок редактора преобразуется во владеющий
`NumericProcessingGraph`, а не выполняется напрямую.

## Превью и отдельные графические панели

Встроенная диагностика наблюдает выходы источников/процессоров и входы
потребителей — точки, которые доставляет канонический движок. Она показывает
доступность, число значений и точное первое числовое значение. Для нескольких
каналов указывается канал первого значения. Structured payload показывает
число байтов; History — filled count кадров, отдельно от capacity.
Диагностика не изменяет параметры и не удерживает кадровые буферы.

Старые кадры, чужие endpoint и несовместимые контракты не заменяют актуальные
значения. Недоступность, смена активной схемы, несовместимая правка черновика
и скрытие редактора очищают превью. Перезапуск сервиса выбранного устройства
с новой epoch очищает диагностику даже при прежней схеме и том же ID устройства;
черновик, параметры и расположение узлов сохраняются. При скрытии снимается только подписка
редактора; обработка и подписки открытых графических панелей продолжаются.

Для поддерживаемого числового выхода контекстное меню узла открывает отдельную
графическую панель. Панели имеют собственное представление; видимость
управляет проекцией и отрисовкой, а не выполнением DSP. Точный scalar caption
отделён от проекции графика в float: разрешённая неточная проекция отмечается,
отказ проекции показывается как недоступность renderer.

History хранится в порядке `[кадр][полоса]`. Возраст новейшего кадра равен нулю.
Герцы и секунды показываются при наличии реальных координат/часов; иначе оси
показывают индексы кадров, полос или значений.

## WLEDOutput, тема и язык

WLEDEncode формирует пакет, WLEDOutput задаёт его отправку. Зарегистрированные
поля WLEDOutput:

| Ключ настройки | Название EN / RU | Значение по умолчанию |
| --- | --- | --- |
| `destination` | Destination IP address / IP-адрес назначения | `255.255.255.255` |
| `interface` | Interface IP address / IP-адрес интерфейса | `0.0.0.0` |
| `port` | Port / Порт | `11988` |
| `cadence_ms` | Send interval, ms / Интервал отправки, мс | `17` |

Порт ограничен диапазоном 1–65535, интервал — 1–60000 мс. IP-адрес назначения
и локального интерфейса проверяются при подготовке. Диагностическая подпись
WLED показывает пиковую частоту, исходную величину и счётчик либо причину
отказа декодирования; она не является подтверждением сетевой доставки.

Тема задаётся централизованно `ui::Theme` (Light, Dark, System), пользовательские
названия — `ui::text`/`ui::bind` (RU, EN). Переключение не переименовывает ключи
конфигурации и не меняет DSP, связи, камеру или пользовательские цвета.

## Границы API

Описание и состояние полей принадлежат `NodeParameterModel` (Qt Core + typed
domain snapshots, без QWidget/QtNodes). Поле имеет явные key/section/order/editor,
варианты, ограничения и availability; секция не выводится из `objectName`.
`NodeParameterForm` создаёт Widgets из этого описания, используя общие
`ui::FieldRow`, `ui::CollapsibleSection` и `ui::ValidationMessage`.
`AudioNodeModel` связывает модель параметров с существующим transactional
редактированием/Undo и остаётся адаптером QtNodes. Будущий QML использует ту же
presentation boundary; Qt не переносится в domain/application/runtime.

Невалидный числовой текст остаётся в состоянии редактирования и сопровождается
описанием допустимого типа/диапазона. Только принятый edit меняет typed node.
Раскрытие секций хранится по node ID в памяти сеанса, отдельно от processing
parameters и сериализованных флагов inline-показа.

`AudioNodeModel::presentation` / `set_presentation` отделяют флаги показа от
числовых параметров. `SchemeEditorWidget::initialize_default_layout` запрашивает
начальную раскладку для первого запуска.

`NumericEditorGraphModel` предоставляет `set_numeric_graph`,
`export_numeric_graph`, `edit_node` и типизированные снимки для Undo/Clipboard.
`SchemeEditorWidget` предоставляет `load_numeric_draft`, `numeric_draft`,
`save_preset`, `load_preset`, `remove_preset`; сигнал `numeric_draft_changed`
уведомляет сохранение черновика. Apply использует `GuiPresenter`, доставка
превью — `numeric_frame_ready` и `numeric_history_ready`. Подписки редактора
объединяются с подписками панелей через `set_editor_numeric_endpoints`.
